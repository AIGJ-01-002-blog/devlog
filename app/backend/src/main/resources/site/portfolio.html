1. 배포 중에도 끊기지 않는 서비스

  • 문제 서버 한 대에 kubectl apply만 하면 새 버전이 안 뜰 때 되돌릴 사람이 없고, 배포 중 요청이 끊길 수 있었어요.
  • 결정 롤링 배포 + 준비 검사(readiness) + 정해진 시간 안에 준비되지 않으면 직전 버전으로 되돌리는 배포 스크립트로 정했어요.
  • 결과 0.1초마다 요청을 보내며 재시작하니 42초 동안 파드 2개가 바뀌었고 요청 892건 중 실패 0건. 일부러 망가뜨린 버전은 60초 뒤 이전 버전으로 돌아왔어요.

근거: 무중단 배포·자동 롤백·터널 · 무중단 배포와 롤백

2. 목록 화면의 N+1 쿼리 없애기

  • 문제 글 20개 목록에서 작성자·태그·댓글 수를 글마다 따로 읽으면 쿼리가 1 + 20 × 3 = 61번 나가요.
  • 결정 "목록당 쿼리 1번"을 규칙으로 두고, 태그는 ARRAY 하위 쿼리, 수는 집계 뷰 조인으로 한 문장에 담았어요.
  • 결과 글 20개 목록에서 SQL 61번 → 1번, p95 16.75ms → 3.93ms(실제 PostgreSQL에서 500회씩, 세 번 잰 중앙값). 이 수는 시험이 매번 다시 세서 규칙이 깨지면 CI가 실패해요.

근거: DB 성능 — 인덱스, 실행 계획, N+1 · 측정 시험 코드

3. 기본값이 조용히 빠진 곳 찾기 (보안 점검)

  • 문제 프레임워크 기본값이 프록시·터널 뒤에서는 빠져, 큰 취약점 대신 조용한 빈틈이 여러 곳 생겼어요.
  • 결정 한 번에 고치지 않고 점검 이슈 하나에 항목을 모아 우선순위대로 한 PR씩 고쳤어요.
  • 결과 HSTS, CSRF 쿠키 속성, DB 연결 대기 30초 → 3초, 외부 API 시간 제한 등 1차에서 7가지를 고쳤어요. 이어서 명령줄 인자로 비밀 키가 보이던 백업 스크립트도 고쳤어요.

근거: 보안 점검 1차에서 고친 일곱 가지 (PR #358) · 열쇠는 명령줄에 두지 않는다

4. AI가 블로그에 글을 쓰게 하는 MCP 서버

  • 문제 AI 에이전트가 글을 쓰고 올리게 하려는데, 웹과 다른 길을 열면 공개 범위·검증 규칙이 갈라지고 AI가 확인 없이 발행·삭제하거나 비밀값을 글에 붙일 수 있었어요.
  • 결정 웹과 같은 서비스를 부르는 MCP 서버(/api/mcp)를 두고, 토큰은 SHA-256 해시로만 저장, 기본 권한은 임시글까지, 발행·삭제는 회원이 웹에서 켤 때만, 토큰·키 모양이 보이면 거절하게 했어요.
  • 결과 도구 24개 중 기본 17개만 보이고, 회원당 1분 60번·쓰기 한 시간 30번으로 막아요. 2026-10-11 ChatGPT에서 OAuth 연결 → 임시글 저장 → 발행 → 삭제까지 확인했어요.

근거: MCP 활용과 구현 — AI에게 내 서비스를 도구로 건네기

5. 근거 없는 노래방 번호는 검색에 내보내지 않기 (jpop.today)

  • 문제 JPOP 3,317곡의 TJ·금영 번호는 대부분 공식 확인 전 관측값이라, 틀린 번호가 담긴 곡 화면까지 검색 엔진에 색인될 수 있었어요.
  • 결정 색인 규칙을 contracts/publication.mjs 한 파일의 함수로 두고, 제공사 조회 근거가 있고 충돌이 없는 공식 확인 곡만 검색에 내보내고, 나머지와 미리보기 빌드는 모두 검색에서 빼기로 정했어요.
  • 결과 제공사 조회 응답을 남기는 대조 기록(ledger)을 99건 → 192건으로 늘려 검색에 내보내는 확인곡이 42곡 → 91곡이 됐고, 근거 없는 3,226곡은 검색에서 빼서(색인 제외) 품질을 지켜요(2026-10-22 운영 빌드 a68df00).

근거: publication.mjs · jpop.today 수록 범위

6. 곱셈 한 번에 코인이 공짜가 되던 버그 (CWE-197)

  • 문제 모의투자에서 수량 × 가격이 long 범위를 넘으면 잘려서, 100개 × 184,467,440,737,095,517 크레딧 주문이 84 크레딧으로 계산됐어요. PR #347의 자동 코드 리뷰(CodeRabbit)가 짚어 알았어요.
  • 결정 곱셈 결과를 검사하는 한 겹 대신, 주문 금액 상한(1조 크레딧)과 수량 상한을 함께 두는 두 겹으로 막았어요.
  • 결과 같은 날 핫픽스 v2.2.1로 배포했어요. 거절 시험에 넘침 주문 2건(84가 되던 주문, 수량 상한 초과)과 주문이 하나도 남지 않는지 확인하는 검사 1개를 더했어요.
