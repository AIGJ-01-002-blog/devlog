# Feature Specification: 쇼츠 스튜디오 1단계 (글 → 대본 → MP4 → 미리보기, 양산형 방지 검사)

**Feature Branch**: `099-shorts-studio` (작업 브랜치 `claude/project-thread-5xa88u`)
**Created**: 2026-10-14
**Status**: Implemented
**근거**: 2026-10-14 블로그 주인 결정 "devlog 2.0 바로 개발"(수익화 방향 판단 스레드), 같은 날 "자동 올리기 말고 수동으로 올리는 가이드로, 양산형처럼 보이는 것을 막는 로직도 만들어 검증하자". 목표 이슈 #236, 할 일 #237·#242.

## 고른 것과 이유

- **대본은 사용자 쪽 AI가 MCP로 쓴다**: 서버가 유료 AI를 부르지 않는다(추가 운영비 월 3만 원 이하). AI는 대본을 저장만 하고, 영상 만들기는 사람이 스튜디오 화면에서 누른다.
- **렌더는 따로 도는 워커(`app/render-worker`, Python + FFmpeg)가 한다**: 워커가 devlog에 일을 받으러 나가는(바깥으로만 여는) 방식이라 학교 방화벽과 상관없고, 맥북 로컬 TTS(`say`, 한국어 목소리)를 쓰면 음성 비용이 0원이다. 쿠버네티스 Pod에 FFmpeg·글꼴을 넣지 않아 운영 이미지가 커지지 않는다.
- **영상은 사진과 같은 저장소(로컬 폴더 또는 MinIO)에 `shorts/` 키로 둔다**: 백업·로컬 이전 때 파일 저장소 하나만 챙기면 된다. 주소는 추측할 수 없는 UUID다(사진과 같은 수준). 
- **양산형 방지 검사는 렌더 직전에 서버가 한다**: YouTube는 2025-07-15부터 틀에 찍어낸 대량 생산 영상을 수익 창출에서 뺀다. 막을 것(렌더 불가)과 경고(통과 가능)를 나누고, 이유와 고칠 방법을 화면·MCP 결과에 그대로 준다. 판정은 문자 3-gram 기반이라 외부 서비스 없이 돈다.
- **2.0.0 전까지는 `SHORTS_ENABLED=false`로 숨긴다**: 다른 1.x 릴리스에 섞여 나가도 화면·API·MCP 도구가 보이지 않는다.
- **자동 업로드는 하지 않는다**: 플랫폼별 직접 올리기 안내는 #238에서 한다.

## 사용자 시나리오

1. **Given** 쇼츠가 켜진 서버와 연결한 AI, **When** "글 103을 쇼츠로 만들어 줘"라고 하면, **Then** AI가 `create_shorts_script`로 장면(자막·내레이션) 3~10개짜리 대본을 저장하고, 검사 결과(점수·막힌 이유·경고)와 스튜디오 링크를 돌려받는다.
2. **Given** 스튜디오(/studio), **Then** 내 쇼츠 목록이 상태(대본·대기·만드는 중·완성·실패)와 함께 보이고, 하나를 열면 장면을 고치고 [검사], [영상 만들기]를 누를 수 있다. 예상 길이가 보인다.
3. **Given** 막힌 이유가 있는 대본, **When** [영상 만들기]를 누르면, **Then** 거절되고 이유(예: "원본 글 문장을 82% 그대로 읽어요")와 고칠 방법이 보인다.
4. **Given** 검사를 통과한 대본, **When** [영상 만들기], **Then** 대기에 들어가고, 워커가 받아 9:16 MP4를 올리면 완성으로 바뀌어 화면에서 재생·내려받기가 된다.
5. **Given** 워커가 꺼져 있음, **Then** 대기 상태에 "렌더 기기가 켜지면 만들어져요"가 보인다. 워커가 15분 넘게 응답이 없으면 작업이 대기로 돌아가고, 3번 실패하면 실패로 끝난다.
6. **Given** 완성된 쇼츠의 대본을 고치면, **Then** 대본 상태로 돌아가고 이전 영상은 지워진다.
7. **Given** 휴대폰, **Then** 목록·편집·미리보기가 한 줄씩 쌓이고 가로로 넘치지 않는다. 모든 버튼에 하는 일을 알리는 툴팁이 있다.

## Requirements

- **FR-001**: `shorts` 테이블에 회원·원본 글(지워지면 비움)·제목·장면(jsonb)·상태·시도 횟수·영상 키·길이·오류·버전을 둔다. 회원이 탈퇴 정리되면 영상 파일과 행을 지운다.
- **FR-002**: 대본 규칙: 제목 1~60자, 장면 최대 10개(영상 만들기는 3개 이상), 자막 1~40자, 내레이션 1~200자, 코드 조각 300자까지. 예상 길이(내레이션 글자 수 ÷ 초당 6.5자 + 장면마다 0.6초)는 60초 이하.
- **FR-003 (양산형 방지, 막기)**: ① 내 다른 쇼츠와 내레이션 3-gram 자카드 유사도 0.6 이상 ② 원본 글 본문에 그대로 있는 내레이션 비율(3-gram 포함도) 0.8 이상 ③ 장면 둘의 유사도 0.6 이상이거나 장면 절반 이상(3개 이상)이 같은 6글자로 시작 ④ 내용 없는 장면(내레이션 8자 미만).
- **FR-004 (경고)**: 내 경험·결과 표현(제가·저는·직접·해 보니·겪·숫자 등)이 한 장면도 없음, 첫 장면이 질문이나 문제 제시가 아님, 원본 글이 없음. 점수 = 100 − 막기 40 − 경고 10 (0 이상).
- **FR-005**: 영상 만들기는 회원당 하루(한국 0시 기준) 10번까지.
- **FR-006 (워커 API)**: `/api/render/jobs/claim`·`/{id}/video`·`/{id}/fail`은 세션·CSRF 없이 `X-Render-Token`(실행 환경 비밀값 `SHORTS_WORKER_TOKEN`)만 본다. 비어 있으면 워커 API는 404다. 받은 작업마다 일회용 claim 값을 주고, 결과는 그 값이 맞을 때만 받는다. 영상은 MP4(ftyp) 20MB 이하만 받는다(인그레스 본문 상한 21m 안). 워커는 3Mbps 안으로 인코딩한다.
- **FR-007**: MCP 도구 `create_shorts_script`·`update_shorts_script`(쓰기)·`list_shorts`(읽기)는 쇼츠가 켜졌을 때만 보인다. 영상 만들기 도구는 없다(사람이 누른다).
- **FR-008**: `/api/auth/me`가 `features.shorts`를 알려 화면이 메뉴를 보일지 정한다.
- **FR-009**: 영어·일본어·중국어 문장을 함께 넣는다(081).

### 2단계: 직접 올리기 안내 (#238)

- **FR-010**: 완성된(READY) 쇼츠에서 YouTube Shorts·Instagram Reels·TikTok을 고르면 붙여 넣을 문구를 만든다. YouTube는 제목 칸 + 설명(첫 장면 내레이션 · 누를 수 있는 글 주소 · 해시태그), Instagram·TikTok은 캡션(제목 · 첫 장면 내레이션 · "전체 글은 고정 댓글" · 해시태그)이다. 캡션 링크를 못 누르는 두 곳은 글 주소를 고정 댓글 문구로만 준다.
- **FR-011**: 해시태그는 바탕 글의 태그를 순서대로 쓰고, 해시태그에 못 쓰는 글자(. + # -)를 빼고, YouTube 3개·Instagram 5개·TikTok 5개까지만 쓴다.
- **FR-012**: 확인 표시: 길이(YouTube·Instagram 180초, TikTok 600초), 9:16, 제목 100자(YouTube), 설명·캡션 5000자(YouTube)·2200자(Instagram·TikTok), 해시태그 수. 한도는 2026-10 각 플랫폼 안내 기준이며 넘쳐도 문구를 자르지 않고 알려만 준다.
- **FR-013**: 올리는 순서는 앱 화면 기준 5단계이고, AI 음성을 쓴 경우 각 플랫폼의 AI·변경된 콘텐츠 표시를 켜라고 안내한다.
- **FR-014**: 휴대폰에서 Web Share API로 파일 공유가 되면 [앱으로 보내기]로 MP4를 넘긴다. 안 되면 [영상 받기]로 안내한다.
- **FR-015**: `shorts_upload`(쇼츠·플랫폼마다 하나)에 올린 영상 주소를 남긴다. `PUT·DELETE /api/me/shorts/{id}/uploads/{platform}`. 주소는 https, 계정 정보·포트 없음, 고른 플랫폼 도메인(youtube.com·youtu.be, instagram.com, tiktok.com·vm/vt.tiktok.com)만 받는다. 남기기는 READY일 때만, 지우기는 언제나. 쇼츠를 지우면 함께 지운다. devlog는 SNS에 아무것도 보내지 않는다.
