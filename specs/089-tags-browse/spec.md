# Feature Specification: 전체 태그 둘러보기 (검색·정렬·태그별 인기 글 줄)

**Feature Branch**: `089-tags-browse`
**Created**: 2026-10-12
**Status**: Implemented (v1.66.0)
**근거**: 블로그 주인 요청(2026-10-12) "우리 태그 페이지가 너무 난잡해서 일단 맨 위에 검색과 필터링을 넣고 무한 스크롤로 내려가는 데 태그 마다 가로 휠로 이어지는 가장 인기있는 태그의 게시물을 보여줘"

## 문제
`/tags`는 상위 100개 태그를 칩으로 한 화면에 늘어놓아, 태그가 늘수록 어디서부터 봐야 할지 알 수 없고 태그 안에 어떤 글이 있는지도 보이지 않았다.

## 바뀌는 것
- 맨 위에 **태그 검색**과 **정렬**(인기순·이름순·최근순)을 둔다. PC에서는 내려도 화면 위에 붙어 따라온다. 휴대폰은 화면이 좁아 따라오지 않는다.
- 그 아래로 **태그 한 줄씩** 인기순(공개 글 수)으로 6개씩 이어 붙인다(무한 스크롤, spec 069의 `InfiniteLoader`).
- 줄마다 **그 태그의 인기 글 카드(최대 10개)**를 가로로 넘겨 본다. 글이 더 있으면 줄 끝에 "+N편 / 전체 보기" 카드가 태그 화면(`/tags/{이름}`)으로 잇는다.
- 줄 머리: `#태그`(태그 화면 링크), "글 N편", "최근 {언제}"(그 태그에 마지막으로 공개된 글), PC에는 [‹]/[›] 버튼(툴팁 "이전 글"·"다음 글", 끝에서는 꺼짐).

## Requirements
- **FR-001**: `GET /api/tags/browse?q=&sort=popular|name|recent&cursor=`는 `{ items: [{ name, postCount, lastUsedAt, posts: PostCard[] }], nextCursor, total }`를 돌려준다. 한 쪽 6줄, `total`(검색어에 맞는 태그 수)은 첫 쪽에만 싣는다.
- **FR-002**: 글 수·인기 글·최근 시각은 공개 목록 조건(010 FR-018)의 글만 센다. 공개 글이 없는 태그는 나오지 않는다.
- **FR-003**: 검색어는 태그 정규화처럼 다듬어(앞의 #, 대문자, 띄어쓰기→-) 이름 **어디에든** 들어 있으면 맞는다. `_`는 와일드카드가 아니다. 30자를 넘으면 결과가 없다.
- **FR-004**: 정렬 — 인기순: 공개 글 수 많은 순, 이름순: 이름 순, 최근순: 마지막 공개 시각 최신 순. 모두 같으면 이름 순. 모르는 정렬 값·망가진 커서는 기본(인기순, 처음부터)이다.
- **FR-005**: 인기 글 순서는 `3×좋아요 + 2×댓글 + 0.1×조회수`(트렌딩 017과 같은 무게, 기간 감쇠 없음), 같으면 처음 공개 최신 순.
- **FR-006**: 검색어·정렬은 주소(`/tags?q=&sort=`)에 남긴다. 기본값은 주소에서 뺀다. 서버는 그 주소의 첫 쪽을 첫 화면 데이터(`browse`)로 함께 내려준다.
- **FR-007**: 검색어가 있는 `/tags?q=` 화면은 `noindex`다(목록의 일부라 따로 수집할 값이 없다). 정렬만 바꾼 주소는 정규 주소가 `/tags`다. 글이 하나뿐인 태그 화면의 `noindex`(spec 085 FR-003)는 그대로다.
- **FR-008**: 새 문구는 영어·일본어·중국어로도 보인다. 아이콘 버튼에는 이름과 툴팁이 있다(spec 055).

## 고른 기본값 (질문 없이 정함)
- **세로 휠을 가로로 바꾸지 않았다.** 페이지 전체가 무한 스크롤이라 휠을 줄이 가로채면 마우스가 줄 위에 있을 때 아래로 내려갈 수 없다. 트랙패드 가로 밀기, Shift+휠, 손가락 밀기, [‹]/[›] 버튼으로 넘긴다. 줄은 카드 단위로 딱딱 멈춘다(scroll-snap).
- **"필터링"은 정렬 세 가지로 했다.** 태그에는 거를 속성(분류·기간)이 따로 없어, 검색어 + 정렬이 velog 태그 화면과 같은 수준이다.
- **휴대폰에서는 다음 카드가 조금 보이게(폭 62%)** 해 옆으로 넘길 수 있다는 걸 알린다. 손가락 화면에는 [‹]/[›]를 숨긴다.
- 서버가 그리는 첫 화면 본문은 상위 100개 태그 링크를 그대로 둔다(스크립트를 돌리지 않는 검색 도구용).
- 태그 줄은 캐시하지 않았다. 공개 태그가 수백 개 수준이라 쪽마다 쿼리 3번(태그·인기 글 번호·카드)이면 충분하다.
