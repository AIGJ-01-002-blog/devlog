# Feature Specification: 네이버 로그인

**Feature Branch**: `096-naver-login`
**Created**: 2026-10-13
**Status**: Implemented (키를 넣으면 켜짐)
**근거**: 2026-10-13 블로그 주인 요청 "네이버 소셜 로그인도 추가해줘". 카카오(080)·Facebook(083) 로그인과 같은 방식이다.

## 사용자 시나리오

1. **Given** 운영자가 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`을 넣은 사이트, **When** 로그인 화면을 열면, **Then** 카카오 아래에 초록 [네이버로 계속하기] 버튼이 보인다. 키가 없으면 버튼이 없다.
2. **Given** 네이버로 처음 온 사람, **When** 네이버 동의 화면을 거치면, **Then** 가입 마무리 화면에서 `nv-` 블로그 주소와 닉네임을 정하고 가입한다. 네이버 별명(없으면 이름)이 닉네임 칸에, 이메일 앞부분이 주소 칸에 미리 들어간다.
3. **Given** 네이버가 이메일을 준 사람, **Then** 이메일을 다시 묻지 않는다. 동의 화면에서 이메일 제공을 끈 사람은 가입 마무리 화면에서 이메일을 받아 인증 메일을 보낸다(이메일 없는 GitHub 계정과 같음).
4. **Given** 네이버로 가입한 회원, **When** 다시 네이버로 로그인하면, **Then** 네이버 사용자 id(앱마다 다른 값)로 같은 계정에 들어온다. 네이버 이메일이 바뀌어도 같은 계정이다.
5. **Given** 회원이 직접 올린 네이버 프로필 사진, **Then** 가입 마무리 화면에서 [네이버 프로필 사진 사용]을 고를 수 있다. 바로 받지 못하면 서버가 대신 받는다(080 FR-007과 같음). 네이버 기본 사진은 넘기지 않는다.

## Requirements

- **FR-001**: 등록 이름은 `naver`, 콜백은 `{SITE_BASE_URL}/login/oauth2/code/naver`. 인가는 `nid.naver.com/oauth2.0/authorize`, 토큰은 `nid.naver.com/oauth2.0/token`, 사용자 정보는 `openapi.naver.com/v1/nid/me`. Client Secret은 요청 본문으로 보낸다.
- **FR-002**: 네이버는 scope를 받지 않는다. 받을 정보는 개발자센터의 "제공 정보 선택"에서 이메일·별명·프로필 사진(필수 또는 추가), 이름(추가)으로 정한다.
- **FR-003**: 사용자 정보는 `response` 안에 온다(`id`, `nickname`, `name`, `email`, `profile_image`). 받은 이메일을 인증된 이메일로 쓴다. 정리 규칙은 다른 소셜과 같다(spec 038).
- **FR-004**: 블로그 주소 접두어는 `nv-`. 이메일 가입 주소는 `nv_`로 시작할 수 없고, 이메일 가입 주소 추천은 `nv_`로 시작하면 밑줄을 뺀다. DB는 `nv-` 접두어와 로그인 수단 NAVER를 더 받는다(V34).
- **FR-005**: 사진은 `https://phinf.pstatic.net`만 받는다. 네이버 기본 사진은 다른 호스트(`ssl.pstatic.net`)라서 자연히 빠진다. 가입 마무리 화면 CSP img-src와 서버 대신 받기 허용 목록에 같은 호스트를 더한다.
- **FR-006**: 설정 화면·메일의 로그인 수단 이름은 "네이버"(영어 Naver, 일본어·중국어 NAVER).

## 고른 것과 이유 (질문 없이 진행, 일일 보고에 기록)

- **주소 접두어 `nv-`**: 다른 소셜처럼 두 글자다. `na-`는 이름(name)이나 "없음(n/a)"으로 읽혀 `nv-`로 골랐다.
- **이메일을 그대로 믿음**: 네이버가 주는 이메일은 네이버 메일 주소이거나 본인 확인을 마친 연락처 이메일이다. 우리 로그인은 이메일이 아니라 (로그인 수단, 네이버 id)로 계정을 찾으므로 이메일이 같다고 다른 계정과 이어지지 않는다.
- **버튼은 네이버 초록(#03C75A)에 흰 글자**: 네이버 로그인 버튼 가이드 그대로다. 흰 글자와 대비가 4.5:1에 못 미치지만, 네이버가 서비스 검수에서 버튼 가이드를 확인하므로 가이드를 따르고 글자를 굵게 했다. 카카오 버튼이 카카오 가이드를 따른 것과 같다.
- **버튼 자리는 카카오 아래**: 국내 서비스(카카오·네이버)를 붙여 두고 그 아래 Facebook·GitHub을 둔다.
- **목표(마일스톤) 밖 작업**: v1.67.0 목표(배포 신뢰도와 릴리스 기록)에 없는 일이라 develop에 머지해 두고 다음 릴리스에 함께 나간다. 네이버 서비스 검수에 며칠이 걸리므로 그동안 키를 넣고 검수를 받으면 된다.
- **개인정보 처리방침은 아직 그대로**: 카카오·Facebook과 같은 이유로 로그인 수단 목록 문구는 한 번에 고치도록 일일 보고 질문에 더한다.

## 운영자가 할 일

1. [네이버 개발자센터](https://developers.naver.com/apps/#/register)에서 애플리케이션을 등록한다. 사용 API는 "네이버 로그인".
2. 제공 정보 선택에서 이메일 주소·별명·프로필 사진을 고르고, 이름은 추가로 둔다.
3. 로그인 오픈 API 서비스 환경에 PC 웹을 더하고 서비스 URL `https://devlog.life`, 네이버 로그인 Callback URL `https://devlog.life/login/oauth2/code/naver`를 넣는다.
4. Client ID·Client Secret을 GitHub Secret `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`에 넣고 배포한다.
5. "개발 중" 상태에서는 멤버관리에 넣은 네이버 아이디만 로그인된다. 모두가 쓰게 하려면 검수 요청(서비스 화면 사진, 로그인 버튼 위치)을 보낸다.
