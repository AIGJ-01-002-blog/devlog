# Feature Specification: 포트폴리오 블로그와 검색 색인 정리

**Feature Branch**: `107-portfolio-seo`
**Created**: 2026-10-21
**Status**: In progress (목표 #443, v2.12.0)
**근거**: 블로그 주인 요청(2026-10-21). devlog.life를 채용 담당자가 읽는 포트폴리오 블로그이자, 검색 엔진에 원하는 글만 색인되는 사이트로 정리한다. 새 모듈·새 인프라·새 의존성은 넣지 않는다. 애드센스는 2~3개월 뒤에 다시 신청하므로 광고는 코드만 준비한다.

## Requirements

### 크롤러와 색인 (US1, #444)
- **FR-001**: robots.txt는 로그인 전용·개인 화면(`/studio`, `/trade`, `/trades`, `/paper`, `/points`, `/shop`, `/dashboard`, `/account/`, `/agreements`, `/oauth/`, `/withdrawn`, 기존 `/api/`·`/admin`·`/write`·`/settings`·인증 화면)을 막는다. 공개 글·목록·소개·태그·검색 결과는 막지 않는다(막으면 noindex 메타를 읽지 못한다).
- **FR-002**: 수집하지 않는 공개 화면 중 독자가 읽는 화면(AI 일기, 짧은 글, 검수 전 외부 회원 글, 태그, 태그 목록, 검색 결과, 글이 없는 블로그·시리즈)은 `noindex, follow`다. 로그인·설정·팔로워 목록 같은 개인 화면은 `noindex, nofollow` 그대로다.
- **FR-003**: `noindex, follow` 화면도 정규 주소·링크 미리보기 머리말과 사이트 바닥글을 둔다. 광고 코드와 RSS 알림은 수집하는 화면에만 둔다.
- **FR-004**: 외부 회원(권한 USER) 글은 운영진(관리자·매니저)이 검수해 `post.index_approved_at`을 채워야 수집 대상이 된다. 운영진 글은 지금처럼 일기 아님·본문 1,000자 이상만 본다.
- **FR-005**: 태그 화면은 글 수와 상관없이 `noindex, follow`다(전에는 직접 쓴 글 2편 이상이면 수집, spec 085·104).
- **FR-006**: 페이지네이션 2페이지 이후 주소는 없다. 목록은 커서로 이어 받는 API(`/api/...?cursor=`)라 화면 주소가 생기지 않는다. 그래서 따로 처리하지 않는다.
- **FR-007**: 관리자 대시보드의 [검색 수집] 칸에 수집하는 글 수, 빼는 글 수(AI 일기·짧은 글·검수 전 외부 글), 검수를 기다리는 외부 회원 글과 [수집 허락] 버튼을 둔다. 앱이 뜰 때 같은 숫자를 로그 한 줄로 남긴다.
- **FR-008**: 사이트맵에는 수집 대상 글만 들어간다(FR-004 포함).

### 주간 회고와 AI 보조 작성 (US2, #445)
- **FR-009**: 매주 일요일 22시(KST)에 그 주(월~일) AI 일기가 있는 회원마다 "YYYY-MM-DD ~ YYYY-MM-DD 주간 회고" 임시글을 하나 만든다(`post.retro_week`, 한 사람에 한 주 하나). 본문은 도입 → 그 주 일기(최대 7편, 소제목 두 단계 내림, 발행한 일기는 원문 링크) → 배운 점이다.
- **FR-010**: 주간 회고는 `## 도입`과 `## 배운 점` 아래에 안내 줄(`> ✍️`)을 뺀 글자(공백 제외)가 각각 100자 이상이어야 발행된다. 웹·MCP 발행 모두 같은 검증(PublishExtension.validate)을 지난다.
- **FR-011**: MCP `update_draft`·`publish_post`는 주간 회고를 거절한다. 사람이 쓴 문단 없이 수집 대상으로 나가는 길을 만들지 않는다.
- **FR-012**: 매일 AI 일기 자동 발행은 그대로 두고 noindex, follow다(FR-002).
- **FR-013**: `post.ai_assisted`는 MCP `create_draft`·`write_devlog`·`update_draft`·`publish_post`, AI 제안으로 쓴 글, AI 일기, 주간 회고에 붙는다. 한 번 붙으면 떼지 않는다. 글 아래(서버 HTML과 화면 모두)에 "AI 보조 작성" 문장과 /about의 글 쓰는 방식 링크를 보여 준다.
- **FR-014**: MCP 발행 기본값은 이미 임시글이다(`create_draft`·`write_devlog`는 임시글만 만든다). 즉시 공개는 사용자가 "AI 발행 허용"을 켠 뒤 `publish_post`를 따로 부를 때만이다. 그래서 기존 호출자에 새 플래그가 필요 없다.

## 고른 기본값과 이유
- 검수 여부는 글 하나에 시각 하나(`index_approved_at`)로 둔다. 누가 허락했는지는 관리 기록에 남기지 않는다. 운영진이 한두 명이라 따로 둘 이유가 아직 없다.
- 검수한 뒤 글쓴이가 글을 고쳐도 허락은 유지한다. 고칠 때마다 다시 검수하게 하면 외부 회원이 글을 다듬을수록 검색에서 빠지는 일이 생긴다. 문제가 되면 운영진이 거두거나 기존 숨기기(spec 019)를 쓴다.
- 기존 글의 AI 보조 작성 표시는 기록으로 확실한 것만 붙인다: AI 일기, AI 글감 제안으로 만든 글, MCP가 붙이는 `## 근거` 목록이 있는 글. 그 밖의 MCP 글은 빠질 수 있어 운영자가 확인한다.
- 회고의 사람 문단 기준은 100자다. 한두 문장으로는 회고라고 보기 어렵고, 더 길게 정하면 쓰는 사람이 부담스럽다.
- 운영진은 `role <> 'USER'`로 본다. 운영자 계정 하나(`OWNER_HANDLE`)만 보면 매니저가 쓴 글이 검수를 기다리게 된다.
