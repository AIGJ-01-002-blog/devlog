# Feature Specification: AI가 쓴 글의 비밀값 막기

**Feature Branch**: `086-ai-secret-guard`
**Created**: 2026-10-11
**Status**: Implemented (v1.63.0)
**근거**: 블로그 주인이 친구에게 받은 질문("로컬 세션 접근 권한에 따른 보안 처리", "블로그 자동 발행이면 토큰 말고 포스팅 내용 필터링 가능한가요")을 코드와 대조해 달라고 요청했다.

## 점검 결과 (2026-10-11)
- MCP 인증은 접근 토큰(개인 토큰·OAuth)만 받고 로그인 쿠키는 보지 않는다. 토큰은 SHA-256으로만 저장하고, 읽기/쓰기 권한·만료·폐기가 있다. 발행·삭제 도구는 회원이 웹에서 "AI 발행 허용"을 켜야 열린다.
- 본문은 화면에 그릴 때 HTML을 걸러 스크립트를 막는다(spec 012).
- 그러나 본문에 비밀값·개인 정보가 들어갔는지는 아무도 보지 않았다. AI에게 "넣지 마세요"라고 안내만 했다.
- AI는 사용자의 컴퓨터에서 파일·환경 변수를 읽을 수 있어 실수로 키를 글에 옮길 수 있다. "AI 일기 쓰기"와 "AI 발행 허용"을 함께 켠 회원은 일기가 사람이 읽지 않고 바로 공개된다.

## Requirements
- **FR-001**: 형식이 뚜렷한 비밀값(devlog·GitHub·Slack 토큰, AI·Google·AWS 키, 개인 키, JWT, 주소 속 비밀번호, 주민등록번호)을 찾는다. 자리표시자(`${...}`, `<...>`, `****`, `password`)와 설명 문장(`ghp_xxx`, `sk-...`)은 넘긴다.
- **FR-002**: `publish_post`는 제목·본문·요약에 비밀값이 보이면 발행하지 않고 실패로 돌려준다.
- **FR-003**: AI 일기 자동 발행은 비밀값이 보이면 임시글로 둔다.
- **FR-004**: `add_note`는 비밀값이 보이는 메모를 받지 않는다.
- **FR-005**: `create_draft`·`write_devlog`·`update_draft`는 임시글을 그대로 저장하되(공개되지 않으므로) 결과에 주의 문장을 덧붙여 AI가 사용자에게 알리게 한다.
- **FR-006**: 찾은 값 자체는 응답·로그에 다시 쓰지 않고 종류만 적는다.

## 고른 기본값 (질문 없이 정함)
- 웹에서 사람이 직접 발행하는 글은 막지 않았다. 사람이 읽고 고른 것이고, 보안 글에서 예시 키를 일부러 쓰는 경우가 있다.
- 오탐으로 글이 막히는 것보다 놓침이 덜 나쁘다고 보고, `password=...` 같은 넓은 규칙과 전화번호·이메일은 넣지 않았다.
