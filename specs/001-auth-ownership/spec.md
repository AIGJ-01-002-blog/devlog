# Feature Specification: 가입·로그인과 소유 권한 (001-auth-ownership)

**Feature Branch**: `001-auth-ownership`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "개발자가 GitHub 계정으로 가입·로그인해 고유한 블로그 주소(/@handle)를 갖고, 자기 글만 고칠 수
있으며, 내 글 관리에서 자기 글을 모아 보는 기능. 상세 규칙은 docs/07-auth.md, docs/08-blog-address.md,
docs/09-nickname.md, docs/42-permission-matrix.md, docs/41-manage-posts.md를 따른다. MVP 첫 릴리스는 GitHub
로그인만 제공하고 이메일·Google은 같은 구조로 다음에 붙인다(2026-10-07 확정)."

**관련 기능 ID**: C-AUTH-1(GitHub 범위), C-AUTH-2(닉네임 변경만), C-OWN-1, C-MANAGE-1

**우선순위 단계**: MVP

## User Scenarios & Testing *(mandatory)*

### User Story 1 - GitHub로 가입하고 블로그 주소를 갖는다 (Priority: P1)

개발자인 방문자가 [GitHub로 계속하기]를 눌러 처음 로그인하면, 가입 마무리 화면에서 닉네임·블로그 주소·필수 약관을
확인하고 가입한다. 가입이 끝나면 그 사람의 블로그 주소 `/@handle`이 정해지고 로그인된 상태가 된다.

**Why this priority**: 이후 모든 쓰기(002 글쓰기·발행)와 공유(003 `/@handle` 블로그)의 전제다. 이것만 있어도
"내 블로그 주소를 갖는다"는 가치가 생긴다.

**Independent Test**: 새 GitHub 계정으로 가입을 끝까지 진행해 `/@gi-...` 주소가 생기고 로그인 상태가 되는지,
같은 GitHub 계정으로 다시 로그인하면 새 계정 없이 같은 계정으로 들어가는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입한 적 없는 GitHub 계정, **When** GitHub 인증을 마치면, **Then** 계정은 아직 만들어지지 않고
   가입 마무리 화면이 열리며 닉네임(GitHub 이름을 규칙에 맞게 정리한 값)과 블로그 주소(`gi-` + GitHub 아이디, 예:
   `octocat` → `gi-octocat`)가 미리 채워져 있다.
2. **Given** 가입 마무리 화면, **When** 필수 약관(이용약관·개인정보 처리방침)에 동의하지 않고 완료를 누르면,
   **Then** 가입되지 않고 동의가 필요하다는 안내가 보인다.
3. **Given** 가입 마무리 화면, **When** 블로그 주소의 `gi-` 뒤 본문을 규칙에 맞게 고치고 완료하면, **Then** 고친 주소로
   가입되고, 동의한 약관의 종류·버전·일자가 기록된다.
4. **Given** 이미 가입한 GitHub 계정, **When** 다시 GitHub로 로그인하면, **Then** 가입 마무리 화면 없이 기존 계정으로
   로그인되고 계정이 새로 생기지 않는다.
5. **Given** 미리 채울 주소가 이미 사용 중, **When** 가입 마무리 화면이 열리면, **Then** `_2`, `_3`처럼 겹치지 않는
   주소가 제안된다.
6. **Given** 두 사람이 같은 블로그 주소(또는 같은 닉네임)로 동시에 가입 완료를 누름, **When** 처리가 끝나면, **Then**
   한 명만 성공하고 다른 사람은 다른 값을 고르라는 안내를 받는다.
7. **Given** 가입한 사용자, **When** 어떤 화면이나 요청으로도 블로그 주소를 바꾸려 하면, **Then** 바뀌지 않는다.
8. **Given** `/@GI-Minseo`처럼 대문자가 섞인 주소, **When** 접속하면, **Then** 소문자 주소 `/@gi-minseo`로 이동한다.

### User Story 2 - 로그인을 유지하고 로그아웃한다 (Priority: P2)

가입한 사용자는 매번 로그인하지 않아도 되고, 공용 PC에서는 로그아웃으로 흔적을 지울 수 있다. 약관이 바뀌거나
계정이 정지되면 그에 맞게 막힌다. 본인 닉네임은 바꿀 수 있다.

**Why this priority**: P1만으로도 가입은 되지만, 로그인 유지·로그아웃·정지·재동의가 없으면 실제 서비스로 열 수 없다.

**Independent Test**: 로그인 후 활동 간격을 두고 다시 접속해 로그인이 유지되는지, 로그아웃 후 쓰기 요청이 거부되고
브라우저 임시 데이터가 지워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 마지막 활동 후 14일 안에 다시 접속하면, **Then** 로그인이 유지된다.
2. **Given** 마지막 활동 후 14일이 지난 사용자, **When** 접속하면, **Then** 비로그인 상태다.
3. **Given** 로그인한 사용자, **When** 로그아웃하면, **Then** 홈으로 이동하고, 이후 쓰기 요청은 거부되며, 그 브라우저에
   남은 본인의 임시 데이터가 지워진다.
4. **Given** 정지된 계정, **When** GitHub로 로그인하면, **Then** 로그인되지 않고 정지 기한과 사유가 안내된다.
5. **Given** 정지되기 전에 로그인해 둔 세션, **When** 쓰기 요청을 보내면, **Then** 거부된다.
6. **Given** 동의한 약관 버전이 현재 버전과 다른 사용자, **When** 로그인하면, **Then** 재동의 화면으로 가고 동의하기 전에는
   다른 화면으로 넘어가지 않는다.
7. **Given** 로그인한 사용자, **When** 닉네임을 규칙에 맞는 새 값으로 바꾸면, **Then** 바로 반영되고 이후 30일 동안은
   다시 바꿀 수 없다는 안내와 함께 거부된다.
8. **Given** 비회원이 로그인이 필요한 화면에 들어옴, **When** 로그인을 마치면, **Then** 원래 보던 화면으로 돌아온다
   (우리 사이트 안의 주소만).

### User Story 3 - 남의 글은 고칠 수 없다 (Priority: P3)

로그인한 사용자는 자기 글만 수정·삭제할 수 있다. 남의 글을 고치려는 요청은 화면을 거치지 않고 직접 보내도 서버에서
거부된다. 남의 비공개·임시 글은 존재하지 않는 글과 똑같이 보인다.

**Why this priority**: 002에서 글이 생기는 순간 필요한 안전장치다. 규칙을 001에서 정해 두어야 002·003이 같은 기준을
쓴다.

**Independent Test**: 사용자 A의 글(테스트용으로 미리 넣은 데이터)에 대해 사용자 B로 수정·삭제 요청을 직접 보내 거부되고
글이 바뀌지 않는지, A의 비공개 글 주소를 B와 비회원이 열면 없는 글과 같은 응답을 받는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자 A의 글, **When** 사용자 B가 수정·삭제 요청을 직접 보내면, **Then** 거부되고 글은 바뀌지 않는다.
2. **Given** 사용자 A의 비공개·임시 글, **When** B나 비회원이 그 주소를 열면, **Then** 존재하지 않는 글과 똑같은
   "찾을 수 없음" 응답과 링크 미리보기를 받는다.
3. **Given** 사용자 A의 비공개 글, **When** A 본인이 열면, **Then** 정상으로 보인다.

---

### User Story 4 - 내 글 관리에서 내 글만 모아 본다 (Priority: P4)

로그인한 사용자는 내 글 관리 화면에서 자기 임시글·발행 글만 본다. 주소나 요청에 다른 사용자 값을 넣어도 본인 글만
나온다.

**Why this priority**: 글 작성(002)과 함께 완성되는 화면이라 001에서는 "본인 글만"이라는 규칙과 빈 상태까지만 다룬다.
목록 탭·필터·더 보기·버튼 동작은 002의 수용 기준에서 다시 확인한다.

**Independent Test**: 글이 없는 사용자로 들어가 빈 상태를 확인하고, 다른 사용자의 글이 있는 상태에서 요청 값을 바꿔도
본인 글만 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 글이 하나도 없는 사용자, **When** 내 글 관리에 들어가면, **Then** 빈 상태 안내가 보인다.
2. **Given** 다른 사용자의 글이 있음, **When** 주소나 요청에 그 사용자 값을 넣어 요청하면, **Then** 본인 글만 보인다.
3. **Given** 비회원, **When** 내 글 관리에 들어오면, **Then** 로그인 화면으로 가고 로그인 후 이 화면으로 돌아온다.

---

### Edge Cases

- GitHub 계정에 인증된 대표 이메일이 없으면? → 가입을 진행하지 않고 "GitHub에서 이메일을 인증한 뒤 다시 시도해
  주세요"로 안내한다(가정 A-3).
- GitHub 이름이 닉네임 규칙(2~10자 한글·영문·숫자)에 맞지 않으면? → 규칙에 맞게 정리한 값을 미리 채우고, 정리할 수
  없으면 빈칸으로 두어 직접 입력받는다. 이미 쓰는 닉네임이면 블로그 주소처럼 뒤에 숫자(2~19)를 붙여 비어 있는 값을
  채우고, 그래도 겹치면 빈칸으로 둔다(2026-10-14, spec 096).
- 가입 마무리 화면에서 오래 머물면? → 소셜 인증 정보는 10분만 유지되고, 지나면 GitHub 인증부터 다시 한다.
- GitHub 로그인 이름(login)을 바꾼 사용자가 다시 로그인하면? → 바뀌지 않는 GitHub 고유 번호로 식별하므로 같은 계정으로
  로그인된다.
- 블로그 주소 본문이 예약어(접두어를 뺀 본문 기준)이거나 형식에 맞지 않으면? → 가입할 수 없고 이유가 안내된다.
- GitHub 아이디가 20자를 넘거나 `-`로 끝나 규칙에 맞지 않으면? → 소문자화·`-`→`_` 변환 뒤 16자로 자르고 끝의 `_`를
  지운 값을 제안한다. 3자 미만이 되면 `user_` + 숫자 6자리로 채운다.
- GitHub 아이디를 나중에 바꾸면? → 블로그 주소는 가입 때 정한 그대로이며 바뀌지 않는다.
- 닉네임에 금칙어를 숫자로 끼워 넣거나(`시1발`) 숫자로 바꿔 쓰면(`sh1t`)? → 거부되며, 어떤 단어에 걸렸는지는 알리지
  않는다. 예외 단어(`시발점`)는 허용된다.
- 자음·모음이 분리된(NFD) 한글을 붙여넣으면? → 합친 형태로 정상 저장된다.
- 로그인 후 돌아갈 주소로 외부 사이트 주소를 넣으면? → 무시하고 홈으로 간다.
- 같은 IP에서 로그인 시도가 몰리면? → 1분에 20회를 넘는 시도는 거부되고, 요청 헤더를 위조해도 이 제한을 우회할 수 없다.
- 로그인 상태 저장소가 일시적으로 멈추면? → 로그인 정보를 읽지 못하는 동안 비로그인으로 처리해 글 읽기는 계속되고,
  새 로그인은 "잠시 후 다시 시도해 주세요"로 안내한다.

## Requirements *(mandatory)*

### Functional Requirements

**가입 (GitHub)**

- **FR-001**: 시스템은 GitHub 인증으로 가입·로그인을 제공해야 한다. 이메일 가입과 Google 로그인은 이번 범위가 아니다.
- **FR-002**: 처음 GitHub로 로그인한 사람은 반드시 가입 마무리 화면을 거쳐야 하며, 완료 전에는 계정을 만들지 않아야 한다.
- **FR-003**: 같은 GitHub 계정(바뀌지 않는 고유 번호 기준)으로는 계정이 하나만 존재해야 한다.
- **FR-004**: 가입할 때 필수 약관(이용약관·개인정보 처리방침)에 동의해야 하며, 동의한 종류·버전·일자를 계정 생성과 함께
  기록해야 한다. 각 약관 문서에는 시행일과 버전이 표시되어야 한다.

**블로그 주소 (docs/08)**

- **FR-005**: 블로그 주소는 `gi-` 접두어 + GitHub 아이디를 소문자로 바꾸고 `-`를 `_`로 바꾼 값으로 미리 채워야 한다.
  자동으로 만든 본문은 16자로 자르고, 겹치면 비어 있는 첫 번호로 `_2`, `_3`을 붙여 제안해야 한다.
- **FR-006**: 사용자는 가입할 때 한 번만 접두어 뒤 본문을 고칠 수 있어야 하고, 가입 후에는 어떤 경로로도 주소를 바꿀 수
  없어야 한다.
- **FR-007**: 형식에 맞지 않거나 예약어(접두어를 뺀 본문 기준)인 주소로는 가입할 수 없어야 한다. 본문은 영문 소문자·
  숫자·`_`로 된 3~20자이며 처음과 끝은 영문·숫자여야 한다. 서비스 이름이 정해질 때까지 `devlog`·`teamblog`도 예약어로
  둔다.
- **FR-007a**: 접두어가 없는 주소(이메일 가입, 이번 범위 밖)는 `go_`·`gi_`로 시작할 수 없어야 한다. 가입 접두어가 붙은
  주소(`go-kim`)와 눈으로 구별하기 어렵기 때문이다. 이 규칙은 검사 규칙에 미리 포함해 이메일 가입이 들어올 때 그대로 쓴다.
- **FR-008**: 같은 주소로 동시에 가입하면 한 명만 그 주소를 가져야 한다.
- **FR-009**: 대문자가 섞인 블로그 주소로 접속하면 소문자 주소로 이동시켜야 한다.

**닉네임 (docs/09)**

- **FR-010**: 닉네임은 2~10자의 완성형 한글·영문·숫자만 허용하고, 자음·모음만, 공백, 특수문자, 이모지, 숫자만으로 된
  값은 거부해야 한다. 분리된 한글(NFD)은 합친 형태로 정규화한 뒤 검사해야 한다.
- **FR-011**: 대소문자만 다른 닉네임은 중복으로 거부해야 하며, 동시에 같은 닉네임을 요청해도 한 명만 성공해야 한다.
- **FR-012**: 금칙어(숫자 삽입·숫자 치환 변형 포함, 예외 목록 허용)와 예약어가 포함된 닉네임은 거부해야 하며, 거부
  메시지는 어떤 단어에 걸렸는지 알려주지 않아야 한다.
- **FR-013**: 사용자는 본인 닉네임을 바꿀 수 있어야 하고, 바꾼 뒤 30일 동안은 다시 바꿀 수 없어야 한다. 이전 닉네임은
  즉시 다른 사람이 쓸 수 있어야 한다.

**로그인 유지·로그아웃 (docs/07 §6·§7)**

- **FR-014**: 로그인은 마지막 활동 시점부터 14일 동안 유지되어야 한다.
- **FR-015**: 로그아웃하면 그 로그인 상태를 즉시 끝내고, 이후 쓰기 요청을 거부하며, 브라우저에 남은 본인의 임시 데이터를
  지워야 한다.
- **FR-016**: 정지된 계정은 로그인할 수 없어야 하며(기한·사유 안내), 정지 전 로그인 상태에서 보낸 쓰기 요청도 거부해야
  한다. 정지 기한이 지난 계정은 로그인할 때 정상 상태로 돌아와야 한다.
- **FR-017**: 저장된 약관 동의 버전이 현재 버전과 다르면 로그인 때 재동의를 받아야 하며, 동의 전에는 다른 화면으로
  넘어가지 않아야 한다.
- **FR-018**: 로그인 후에는 원래 보던 화면으로 돌아가야 하며, 돌아갈 주소는 우리 사이트 안의 주소만 허용해야 한다.
- **FR-019**: 같은 IP의 로그인 시도는 1분에 20회로 제한해야 하며, 위조한 요청 헤더로 이 제한을 우회할 수 없어야 한다.
- **FR-020**: 로그인 상태 저장소를 일시적으로 읽을 수 없을 때는 비로그인으로 처리해 읽기를 계속 제공하고, 새 로그인은
  다시 시도하라는 안내로 거부해야 한다.

**소유 권한 (docs/42, C-OWN-1)**

- **FR-021**: 글의 수정·삭제는 작성자 본인만 할 수 있어야 하며, 이 검사는 화면이 아니라 서버에서 매 요청마다 해야 한다.
- **FR-022**: 볼 권한이 없는 글(남의 비공개·임시·휴지통·숨긴 글)은 존재하지 않는 글과 똑같은 응답과 링크 미리보기를
  돌려줘야 한다.

**내 글 관리 (docs/41, C-MANAGE-1 중 001 범위)**

- **FR-023**: 내 글 관리는 로그인한 본인의 글만 보여줘야 하며, 주소·요청에 사용자를 지정하는 값을 받지 않아야 한다.
- **FR-024**: 글이 없을 때는 빈 상태 안내를 보여줘야 하고, 비회원은 로그인 화면으로 보낸 뒤 로그인 후 돌아오게 해야 한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 한 사람이자 한 블로그. 블로그 주소(handle, 가입 후 불변), 닉네임과 마지막 변경 일자, 상태(정상·정지),
  기본 공개 범위를 가진다.
- **로그인 수단(AuthIdentity)**: 회원이 어떤 수단으로 로그인하는지. 이번 범위에서는 GitHub 하나이며, GitHub 고유 번호,
  인증된 이메일, 마지막 로그인 일자를 가진다. 회원 하나에 로그인 수단 하나.
- **약관 동의(MemberAgreement)**: 회원별·약관 종류별 동의한 버전과 일자.
- **정지 이력(MemberSuspension)**: 정지 기간·사유·해제 일자. 이번 범위에서는 읽기만 한다(정지 처리 기능은 범위 밖).
- **글(Post)**: 이번 범위에서는 소유자 판정과 내 글 관리 목록에만 쓰인다. 작성 기능은 002.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 온 개발자가 GitHub 인증부터 가입 완료까지 2분 안에 마칠 수 있다.
