# Feature Specification: 회원 탈퇴·복구 (020-withdraw)

**Feature Branch**: `020-withdraw`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "회원이 설정에서 잃게 되는 것을 확인하고 본인 확인을 거쳐 탈퇴하면 즉시 모든 기기에서 로그아웃되고
블로그와 글이 보이지 않는다. 30일 안에 로그인해 [복구하기]를 누르면 모두 돌아오고, 30일이 지나면 개인 데이터를 정리해 익명
처리하되 블로그 주소는 영구히 예약해 아무도 다시 쓸 수 없다. 상세 규칙은 docs/44-withdraw.md와 docs/13-delete-withdraw.md
§3(탈퇴 데이터 정책)을 따른다."

**관련 기능 ID**: 회원 탈퇴 (docs/01 §2-3 Tier C, 데이터 정책은 docs/13 §3 확정)

**선행 기능**: `001-auth-ownership` (로그인·세션, 설정, 약관 동의·정지 이력, 블로그 주소)

**우선순위 단계**: 이후 단계 (Tier C)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 잃게 되는 것을 확인하고 탈퇴한다 (Priority: P1)

회원이 설정 맨 아래 [회원 탈퇴]로 `/settings/withdraw`에 들어가, 한 화면에서 안내를 읽고 확인 체크와 본인 확인을 마친 뒤 탈퇴한다.

**Why this priority**: 탈퇴 신청이 있어야 유예·복구·익명 처리가 시작된다.

**Independent Test**: 글 24개·남의 글 댓글 18개·받은 좋아요 126개인 회원이 탈퇴 화면에서 그 숫자와 복구 기한, "블로그 주소는 다시 쓸 수 없어요"를
보는지, 체크·확인 문구 없이 요청하면 서버도 거부하는지, 탈퇴하면 모든 기기에서 로그아웃되고 블로그·글이 "찾을 수 없음"이 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 설정 맨 아래 [회원 탈퇴]를 누르면, **Then** `/settings/withdraw`가 열린다.
2. **Given** 탈퇴 화면, **When** 열면, **Then** 한 화면에 ① "탈퇴하면 이렇게 돼요": 블로그 @주소와 글 N개가 바로 보이지 않음, 남의 글에 쓴 댓글 N개가
   "탈퇴한 사용자의 댓글이에요"로 가려짐, 30일(기한 날짜·시각까지) 안에 다시 로그인하면 모두 복구 가능, 30일이 지나면 글·사진·받은 좋아요 N개가
   완전히 삭제되어 되돌릴 수 없음(답글이 달린 댓글은 내용 없이 자리만 남음), 블로그 주소 @주소는 다른 사람도 나도 다시 쓸 수 없음 + "☐ 위 내용을
   확인했어요", ② 본인 확인이 보인다.
3. **Given** 탈퇴 화면의 숫자, **When** 화면을 열면, **Then** 내 글 수(휴지통 포함 전체), 남의 글에 쓴 댓글 수, 받은 좋아요 합이 그 시점 기준으로 보인다.
4. **Given** 소셜(GitHub) 가입 회원, **When** 본인 확인을 하면, **Then** "탈퇴"를 직접 입력해야 한다. 다르게 입력하면 확인 문구 불일치로 거부된다.
5. **Given** ① 체크와 ② 본인 확인 중 하나라도 빠짐, **When** 보면, **Then** [탈퇴하기]가 비활성이고, 요청을 직접 보내도 서버가 거부한다.
6. **Given** [탈퇴하기], **When** 화면을 열면, **Then** 빨간색이지만 기본 선택(초점)이 아니어서 Enter로 바로 눌리지 않는다.
7. **Given** 조건을 갖춤, **When** [탈퇴하기]를 누르면, **Then** 탈퇴 신청 상태가 되고 모든 기기에서 즉시 로그아웃되며, `/withdrawn` 완료 화면에
   "탈퇴 신청이 완료됐어요 / 기한까지 로그인하면 복구할 수 있어요 / 그동안 블로그와 글은 다른 사람에게 보이지 않아요 [홈으로]"가 보이고, 브라우저에
   남은 임시 글 데이터가 지워진다.
8. **Given** 탈퇴 신청 직후, **When** 다른 사람이 보면, **Then** 블로그 `/@주소`와 내 글이 모두 "찾을 수 없음"이고 목록·피드·트렌딩·수에서 빠지며, 내가
   쓴 댓글은 "탈퇴한 사용자의 댓글이에요"로 가려진다.
9. **Given** 이메일이 있는 계정, **When** 탈퇴가 접수되면, **Then** 복구 기한을 알리는 탈퇴 접수 메일이 간다.
10. **Given** 관리자 권한이 있는 회원, **When** 탈퇴하려 하면, **Then** "관리자 권한을 해제한 뒤 탈퇴할 수 있어요"로 거부된다.
11. **Given** 탈퇴 화면, **When** 보면, **Then** 탈퇴 사유를 묻지 않는다.

### User Story 2 - 30일 안에 로그인해 복구한다 (Priority: P2)

탈퇴 신청한 회원이 30일 안에 로그인하면 복구 화면만 보이고, [복구하기]를 눌러야 블로그·글·댓글이 원래대로 돌아온다.

**Why this priority**: 실수나 마음이 바뀐 경우를 되돌리는 안전장치다. 탈퇴(P1)가 있어야 의미가 있다.

**Independent Test**: 탈퇴 신청 회원이 로그인하면 `/account/restore`만 보이고 다른 주소로 가도 되돌아오는지, [복구하기] 후 블로그·글·댓글·
팔로우 관계·반응 수가 탈퇴 전과 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** 탈퇴 유예 회원, **When** 로그인하면, **Then** `/account/restore`에 "탈퇴 신청한 계정이에요 / 기한까지 복구할 수 있어요 (N일 남음) / 복구하면
   블로그·글·댓글이 모두 원래대로 돌아와요 [로그아웃] [복구하기]"가 보인다. 로그인만으로 자동 복구되지 않는다.
2. **Given** 탈퇴 유예 회원, **When** 다른 화면이나 기능을 요청하면, **Then** 화면은 복구 화면으로 돌아오고, 요청은 계정 상태(탈퇴 신청) 이유로
   거부된다.
3. **Given** 복구 화면, **When** [복구하기]를 누르면, **Then** 정상 상태로 돌아오고 홈에서 "다시 오신 걸 환영해요"가 보이며, 블로그·글·댓글·관계·
   반응 수가 탈퇴 전과 같고, 이메일이 있으면 복구 완료 메일이 간다.
4. **Given** 복구 화면, **When** [로그아웃]을 누르면, **Then** 로그아웃만 되고 유예는 계속된다.
5. **Given** 탈퇴 유예 중, **When** 다른 사람이 닉네임·블로그 주소를 쓰려 하면, **Then** 쓸 수 없다(묶어 둔다).
6. **Given** 탈퇴 유예 중, **When** 그 회원에게 새 알림이 생길 일이 있거나 그 회원의 행동으로 알림이 생길 일이 있으면, **Then** 알림을 만들지
   않는다(알림 기능이 있을 때).

### User Story 3 - 30일이 지나면 개인 데이터를 정리하고 익명 처리한다 (Priority: P3)

유예 30일이 지난 회원은 매일 새벽 정리에서 글·댓글·좋아요·사진·로그인 수단·관계·알림·신고 데이터를 정해진 순서로 정리한 뒤 익명 껍데기로
남는다. 블로그 주소만 영구히 남아 아무도 다시 쓸 수 없다.

**Why this priority**: 개인정보를 실제로 지우는 마무리지만, 유예 기간(30일)이 지나야 동작한다.

**Independent Test**: 탈퇴 신청 31일 된 회원에 대해 정리를 실행해 결과가 docs/13 §5 "회원 탈퇴 데이터" 기준과 docs/44 §5 기준을 만족하는지,
중간 단계에서 일부러 실패를 일으키면 그 회원의 모든 단계가 되돌려지고 다음 날 다시 시도되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 탈퇴 신청 후 30일이 지난 회원, **When** 매일 새벽 정리가 돌면, **Then** 그 회원 1명의 정리 단계가 정해진 순서대로 모두 성공하거나 모두
   취소된다.
2. **Given** 정리 완료, **When** 결과를 보면, **Then** 내 글(휴지통 포함)은 완전히 삭제되고 그 글에 남이 쓴 댓글·좋아요·알림도 함께 지워진다.
3. **Given** 남의 글에 쓴 내 댓글, **When** 정리되면, **Then** 답글이 달린 댓글만 내용을 비우고 "탈퇴한 사용자의 댓글이에요"로 자리만 남고, 나머지는
   지워지며, 그 글의 댓글 수가 실제와 맞는다.
4. **Given** 내가 누른 좋아요, **When** 정리되면, **Then** 지워지고 그 글의 좋아요 수가 실제와 맞는다.
5. **Given** 내가 올린 사진(지금 프로필 사진 포함), **When** 정리되면, **Then** 다음 사진 정리 때 파일과 기록이 지워진다(탈퇴 신청 뒤 30일 + 정리 한 번보다
   오래 남지 않는다).
6. **Given** 로그인 수단, **When** 정리되면, **Then** 지워지고, 같은 GitHub 계정으로 다시 가입하면 새 계정이 된다.
7. **Given** 친구·팔로우 관계와 받은 알림, **When** 정리되면, **Then** 양방향 관계가 지워지고 받은 알림이 지워지며 묶음 알림에서 나는 빠진다.
8. **Given** 내 콘텐츠에 대한 대기 신고 사건, **When** 정리되면, **Then** "대상 없음"으로 닫히고(처리 일자 기록, 처리자 없음), 내가 쓴 신고의 설명은
   비워진다(행·사유는 유지).
9. **Given** 회원 행, **When** 마지막에 익명 처리되면, **Then** 닉네임·소개·닉네임 변경 일자·최근 활동 일자가 비워지고, 블로그 주소는 그대로 남는다. 약관·
   AI 동의 기록과 정지 이력은 지우지 않는다.
10. **Given** 익명 처리 후, **When** `/@옛주소`를 열면, **Then** "찾을 수 없음"이고, 누구도(본인 포함) 그 주소로 가입할 수 없다. 남은 댓글은 작성자
    "탈퇴한 사용자", 기본 회색 아이콘으로 보인다.
11. **Given** 익명 처리 후, **When** 다른 사람이 그 닉네임을 쓰려 하면, **Then** 바로 쓸 수 있다.
12. **Given** 익명 처리 후 같은 GitHub 계정으로 가입, **When** 블로그 주소를 정하면, **Then** 옛 주소는 예약되어 있어 `kim755030_2`처럼 다른 주소가 된다.
13. **Given** 정리 확정 후, **When** 로그인 상태 보관소를 보면, **Then** 그 회원의 세션·토큰·실패 횟수·요청 횟수 기록이 지워져 있다.

### Edge Cases

- 정리 중 한 단계가 실패하면? → 그 회원의 앞 단계까지 모두 되돌리고 다음 날 다시 시도한다. 다른 회원 정리에는 영향이 없다.
- 탈퇴 유예 중 정지할 수 있나? → 없다. 탈퇴 신청 상태는 정지 상태로 바꿀 수 없다.
- 정지된 회원은 탈퇴할 수 있나? → 로그인할 수 없으므로 정지 기간에는 탈퇴할 수 없다.
- 복구 화면에서 아무것도 안 하고 30일이 지나면? → 예정대로 정리된다.
- 탈퇴 유예 회원의 비밀번호 재설정은? → 로그인 전 기능이라 가능하다(이메일 가입이 있을 때).
- 탈퇴 유예 회원이 같은 수단으로 새로 가입하려 하면? → "탈퇴 신청한 계정이 있어요. 로그인하면 복구할 수 있어요"가 보인다. 탈퇴 신청 여부가 드러나는
  것은 감수한다.
- 탈퇴한 회원 콘텐츠의 신고 스냅샷은? → 30일 뒤 처리에서 사건이 닫히고 그로부터 30일 뒤 비워지므로 탈퇴 신청부터 최대 약 60일 남는다.
- 탈퇴 유예 중 내가 누른 좋아요는? → 그대로 두어 반응 수가 유지된다. 내 댓글은 행은 그대로이고 화면에서만 가린다(유예 중에는 댓글 수에 포함).
- 30일 뒤 처리로 생기는 사건은? → 없다(글 완전 삭제로 생기는 글 삭제 사건은 글 기능의 규칙을 따른다).

## Requirements *(mandatory)*

### Functional Requirements

**탈퇴 화면 (W-1 ~ W-4, W-6)**

- **FR-001**: 설정(`/settings`) 맨 아래 [회원 탈퇴]에서 `/settings/withdraw`로 들어가야 한다.
- **FR-002**: 한 화면 안에 ① 안내·확인 체크 → ② 본인 확인 → [탈퇴하기]를 두고, ①을 체크하고 ②를 채워야 버튼이 활성화되어야 한다. 서버도 둘 중
  하나라도 없으면 거부해야 한다.
- **FR-003**: 안내에는 내 글 수(휴지통 포함), 남의 글에 쓴 댓글 수, 받은 좋아요 합(화면을 열 때 계산), 복구 기한(날짜·시각), 30일 뒤 완전 삭제와
  답글 달린 댓글의 자리 남김, "블로그 주소는 다른 사람도, 나도 다시 쓸 수 없어요"를 보여야 한다.
- **FR-004**: 탈퇴 사유는 받지 않아야 한다.
- **FR-005**: [탈퇴하기]는 기본 선택(초점)이 아니어야 한다.
- **FR-006**: 관리자 권한이 있으면 "관리자 권한을 해제한 뒤 탈퇴할 수 있어요"로 거부해야 한다(상태 충돌).

**본인 확인 (docs/13 §3-1, W-8)**

- **FR-007**: 소셜 가입은 "탈퇴"를 직접 입력해야 하고, 다르면 확인 문구 불일치로 거부해야 한다.
- **FR-008**: 이메일 가입은 현재 비밀번호를 확인해야 하고, 틀리면 비밀번호 불일치로 거부하며, 5번 연속 틀리면 15분 동안 탈퇴를 시도할 수 없어야 한다
  (docs/11 §6-2와 같은 규칙).

**즉시 효과 (docs/13 §3-1·§3-2, W-5)**

- **FR-009**: 탈퇴하면 즉시 탈퇴 신청 상태와 신청 일자를 기록하고, 그 회원의 모든 세션을 지워 모든 기기에서 로그아웃시켜야 한다.
- **FR-010**: 블로그 `/@주소`와 내 글은 즉시 "찾을 수 없음"이고 모든 목록에서 빠져야 한다. 이는 공개 목록 공용 조건(작성자 탈퇴 신청 제외)과 상세
  읽기 판정으로 처리하며, 각 목록이 따로 처리하지 않는다.
- **FR-011**: 내가 쓴 댓글은 행을 그대로 두고 화면에서만 "탈퇴한 사용자의 댓글이에요"로 가려야 한다.
- **FR-012**: 내가 누른 좋아요는 유예 중 그대로 두어야 한다.
- **FR-013**: 닉네임과 블로그 주소는 유예 중 다른 사람이 쓸 수 없게 묶어 두어야 한다.
- **FR-014**: 완료 화면 `/withdrawn`(로그아웃 상태)에 복구 기한과 [홈으로]를 보여야 하고, 브라우저의 임시 글 데이터는 로그아웃과 같이 지워야 한다.
- **FR-015**: 이메일이 있는 계정에는 복구 기한을 알리는 탈퇴 접수 메일을 보내야 한다.

**유예 중과 복구 (W-9, docs/42 P-12)**

- **FR-016**: 유예 30일 동안 로그인은 가능하되 복구 화면(`/account/restore`)만 보여야 한다. 다른 화면은 복구 화면으로 되돌리고, 다른 요청은 계정 상태
  (탈퇴 신청) 이유로 거부해야 한다.
- **FR-017**: 로그인만으로 자동 복구하지 않고, [복구하기]를 눌러야 정상 상태로 되돌리고 신청 일자를 비워야 한다. 복구하면 블로그·글·댓글·관계·
  반응이 모두 원래대로여야 하고 "다시 오신 걸 환영해요"를 보여야 한다.
- **FR-018**: [로그아웃]은 로그아웃만 하고 유예를 유지해야 한다.
- **FR-019**: 이메일이 있는 계정에는 복구 완료 메일을 보내야 한다.
- **FR-020**: 유예 중 같은 수단으로 가입하려 하면 "탈퇴 신청한 계정이 있어요. 로그인하면 복구할 수 있어요"를 보여야 한다(가입 여부 노출 감수, 회의 P2).
- **FR-021**: 유예 중 비밀번호 재설정은 가능해야 한다(이메일 가입이 있을 때).
- **FR-022**: 유예 중에는 그 회원에게, 그리고 그 회원의 행동으로 새 알림을 만들지 않아야 한다.

**30일 뒤 처리 (docs/13 §3-3, docs/44 §4)**

- **FR-023**: 매일 새벽 한 서버에서만, 탈퇴 신청 후 30일이 지나고 아직 익명 처리되지 않은 회원을 회원 1명씩 처리해야 한다. 한 회원의 모든 단계는
  하나의 단위로 전부 성공하거나 전부 취소되어야 하며, 실패한 회원만 다음 날 다시 시도해야 한다.
- **FR-024**: 각 기능이 자기 정리 단계를 순서 번호와 함께 끼워 넣는 구조여야 하고, 단계는 순서 번호대로 실행되어야 한다. 번호는 10 단위로 두고 새
  단계는 사이 값을 써서 기존 번호를 바꾸지 않아야 한다.
- **FR-024a**: (2026-10-12 민서님 결정, 처리방침 3절과 맞춤) 친구 관계(요청 중·수락 모두, 양쪽)는 30일 정리를 기다리지 않고 탈퇴 신청과 같은 트랜잭션에서 지운다. 복구해도 되살리지 않는다. 아래 (60) 단계는 이 결정 전에 탈퇴한 회원을 위해 남긴다.
- **FR-025**: 단계와 순서는 다음과 같아야 한다: (10) 내 글 전부(휴지통 포함) 완전 삭제와 그 글의 대기 신고 종료, 남이 쓴 댓글·좋아요·알림 함께 삭제 →
  (20) 남의 글에 쓴 내 댓글: 답글이 있으면 내용 비움·자리만, 없으면 삭제, 댓글 수 감소 → (30) 내가 누른 좋아요 삭제·좋아요 수 감소 → (40) 내가 올린
  사진 전부(지금 프로필 사진 포함)를 떼어 다음 사진 정리 때 바로 지워지게 기록 → (50) 로그인 수단 삭제 → (60) 친구 관계(요청 중·수락 모두, 양쪽)
  삭제 → (65) 팔로우 관계 양방향 삭제 → (70) 받은 알림 삭제, 묶음 알림에서 나를 빼고 다시 계산 → (80) 내 콘텐츠의 대기 신고 사건 "대상 없음"(처리 일자
  기록, 처리자 없음), 내가 쓴 신고의 설명 비움 → (90) 회원 행 익명 처리 → (확정 후) 로그인 상태 보관소의 세션·토큰·실패 횟수·요청 횟수 기록 삭제.
- **FR-026**: 내 글 삭제가 맨 먼저여야 하고(이후 단계가 다룰 데이터가 줄어든다), 댓글·좋아요 단계는 그 다음에 실행해 반응 수를 실제 행 수와 맞춰야
  하며, 익명 처리가 맨 마지막이어야 한다.
- **FR-027**: 익명 처리는 닉네임·소개·닉네임 변경 일자·최근 활동 일자를 비우고 익명 처리 일자를 기록해야 한다. 블로그 주소는 그대로 두어야 한다.
- **FR-028**: 약관·개인정보·AI 동의 기록과 정지 이력은 지우지 않아야 한다(동의 증빙·재가입 악용 확인, 2026-10-07 회의 E3·E6).
- **FR-029**: 30일 뒤 처리는 사건을 만들지 않아야 한다. 개인정보 삭제를 유실될 수 있는 사건에 맡기지 않는다.
- **FR-030**: 조회수 관련 개인 데이터는 별도 정리 단계가 없어야 한다(중복 판정 기록은 기간이 지나면 사라지고, 일별 조회 기록은 글 삭제 때 함께
  지워진다).

**익명 처리 후 (docs/13 §3-4, D-8 ~ D-11)**

- **FR-031**: 블로그 주소는 영구 보존하고 재사용할 수 없어야 한다. `/@옛주소`는 "찾을 수 없음"이어야 한다.
- **FR-032**: 닉네임은 익명 처리 뒤 바로 다른 사람이 쓸 수 있어야 한다(30일 뒤 해제).
- **FR-033**: 남은 댓글은 작성자 "탈퇴한 사용자", 내용 "탈퇴한 사용자의 댓글이에요", 기본 회색 아이콘으로 보여야 한다.
- **FR-034**: 같은 수단으로 다시 가입하면 새 계정이 되어야 하고, 옛 주소는 예약되어 있어 다른 주소를 써야 한다.
- **FR-035**: 탈퇴 회원 콘텐츠의 대기 신고 스냅샷은 사건이 닫힌 뒤 30일이 지나 비워지는 기존 규칙을 그대로 따라야 한다(탈퇴 신청부터 최대 약 60일).

**사건 연동 (docs/20 §3-6)**

- **FR-036**: 탈퇴 신청이 확정된 뒤 "회원 탈퇴 신청됨"(회원, 신청 일자)을, 복구가 확정된 뒤 "회원 복구됨"(회원, 복구 일자)을 알려야 한다. 세션
  삭제는 사건에 맡기지 않고 탈퇴 처리가 직접 해야 한다.

**권한 (docs/42 §9)**

- **FR-037**: 회원 탈퇴는 비회원 불가(로그인 필요), 인증 전 회원과 회원 본인은 가능해야 하고, 남을 탈퇴시킬 수 없어야 한다. 정지 회원은 로그인할 수
  없어 정지 기간에는 탈퇴할 수 없다. 서버가 매번 다시 확인한다.
- **FR-038**: 탈퇴 유예 회원은 정지 상태로 바꿀 수 없어야 한다.
- **FR-039**: 관리자(매니저 제외)는 관리자 페이지 회원 화면에서 탈퇴 유예 회원을 30일을 기다리지 않고 바로 정리할 수 있어야 한다. 본인이 바로 지워 달라고
  했을 때 쓰고, 확인 창을 거친다. 정리 단계·결과는 30일 정리와 같다(로그인 수단을 지워 같은 소셜 계정은 새로 가입, 블로그 주소는 계속 예약). 탈퇴 유예가
  아니거나 이미 정리한 회원은 409 NOT_WITHDRAWN. 탈퇴 유예 회원 화면에는 정지 칸을 보이지 않는다(FR-038). (2026-10-10, 민서님 요청 "그냥 삭제
  해주고 테스트 할 수 있어?")

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 001에서 정의. 상태(정상·정지·탈퇴 유예), 탈퇴 신청 일자, 익명 처리 일자를 더한다. 익명 처리 후에는 블로그 주소만 남는 껍데기다.
- **로그인 수단(AuthIdentity)**: 001에서 정의. 30일 뒤 지워 같은 수단으로 재가입할 수 있게 한다.
- **약관 동의(MemberAgreement)·정지 이력(MemberSuspension)**: 익명 처리 후에도 남긴다.
- **정리 단계(Withdrawal Purge Step)**: 기능별 정리 처리와 순서 번호. 회원 1명 단위로 순서대로 실행된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 안내 확인 체크와 본인 확인 없이 탈퇴가 처리되는 경우가 0건이다(화면·서버 모두).
- **SC-002**: 비밀번호를 5번 연속 틀리면 15분 동안 탈퇴 시도가 0건 통과한다(이메일 가입이 있을 때).
- **SC-003**: 탈퇴하면 모든 기기에서 즉시 로그아웃되고(남은 세션 0개), 완료 화면에 복구 기한이 보이며, 블로그와 글이 다른 사람에게 보이는 경우가 0건이다.
- **SC-004**: 유예 중 로그인하면 복구 화면만 보이고, 다른 주소로 가도 100% 복구 화면으로 돌아온다.
- **SC-005**: [복구하기]를 누르면 블로그·글·댓글이 탈퇴 전과 같다.
- **SC-006**: 관리자 권한이 있는 계정이 탈퇴되는 경우가 0건이다.
- **SC-007**: 30일 뒤 처리는 회원 1명 단위로 전부 성공하거나 전부 취소되고, 처리 후 댓글 수·좋아요 수가 실제 행 수와 100% 맞는다.
- **SC-008**: 정리 단계가 순서 번호대로 실행되고, 한 단계가 실패하면 앞 단계까지 모두 되돌려진다.
- **SC-009**: 30일 뒤에는 이메일·닉네임·소개·최근 활동 일자가 남지 않고, 사진은 다음 사진 정리 뒤 남지 않으며, 블로그 주소는 다른 사람이 쓸 수 없다.
- **SC-010**: 답글이 달린 댓글만 "탈퇴한 사용자의 댓글이에요"로 남는다.
- **SC-011**: 같은 수단으로 다시 가입하면 새 계정이 만들어진다.
- **SC-012**: 30일 뒤 처리 후 내 콘텐츠의 대기 신고는 "대상 없음"이고, 내가 쓴 신고의 설명은 비어 있으며, 동의·정지 이력은 남아 있다.
- **SC-013**: 처리 후 회원 행에 블로그 주소 외 개인 정보(닉네임·소개·닉네임 변경 일자·최근 활동 일자)가 남는 경우가 0건이다.
- **SC-014**: docs/13 §5 "회원 탈퇴 데이터" 기준 6개와 docs/44 §5 기준 9개가 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1 (2026-10-07 확정)**: MVP 로그인은 GitHub 단독이므로 본인 확인은 "탈퇴" 입력 방식만 쓴다. 비밀번호 확인·5회 15분 잠금·비밀번호 재설정은 이메일
  가입이 들어올 때 함께 적용한다. 탈퇴·복구 메일은 GitHub의 인증된 대표 이메일로 보낸다.
- **A-2**: 2026-10-07 동의·정지 이력 분리 결정(E2·E3·E6)에 따라 docs/44 §4의 "회원 행의 AI 동의 일자·정지 기한·정지 사유를 비움"은 해당 값이 회원 행에
  없어졌으므로 적용하지 않고, AI 동의를 포함한 동의 기록과 정지 이력은 남긴다. docs/44 §5 #9의 개인 정보 목록도 이에 맞춰 읽는다.
- **A-3**: 친구·팔로우·알림·신고·좋아요·댓글·사진 정리 단계는 해당 기능이 있을 때 그 기능이 끼워 넣는다. 친구 정리는 친구 맺기가 공통이므로 항상
  실행한다(2026-10-07 회의 M1).
- **A-4**: 정지 중 탈퇴 요청 경로와 영구 정지 계정의 개인정보 보유 기간은 미정이다(미결, docs/13 §3-2 검증 M11).
- **A-5**: 탈퇴 전 글 내보내기, 메일로만 가입·탈퇴 상태를 알리는 방식(B안)은 개인 확장으로 범위 밖이다.
- **A-6**: 각 정리 단계의 순서 번호 값(특히 댓글·사진·팔로우·알림)은 담당자 확인 요청 상태이며, docs/44 §4 표의 값을 기준으로 한다.
- **A-7**: 글 삭제·휴지통(C-POST-5)의 완전 삭제 규칙은 글 기능 쪽에서 정의되며, 이 spec은 탈퇴 정리 단계에서 그 규칙을 호출한다.
