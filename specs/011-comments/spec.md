## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글에 댓글을 단다 (Priority: P1)

글을 읽은 회원이 글 아래 입력칸에 댓글을 쓰고 [등록]을 누르면, 댓글이 목록 끝에 `닉네임 @블로그주소`와 함께 나타나고 댓글 수가
하나 늘어난다. 비회원은 댓글을 읽을 수만 있다.

**Why this priority**: 독자와 작성자가 대화하는 가장 기본 기능이다. 이것만으로도 "반응이 있는 블로그"라는 가치가 생긴다.

**Independent Test**: 공개 글에 회원으로 댓글을 쓰고 비회원으로 열어 댓글과 댓글 수가 보이는지, 비회원이 쓰려 하면 거부되는지,
HTML을 쓴 댓글이 글자 그대로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 공개 글을 연 회원, **When** 댓글을 쓰고 [등록]을 누르면, **Then** 댓글이 작성자 프로필 사진(없으면 기본 아이콘),
   `닉네임 @블로그주소`, "방금 전" 같은 시각과 함께 보이고 머리말의 "댓글 N"이 하나 늘어난다.
2. **Given** 글 작성자가 자기 글에 댓글을 씀, **When** 댓글이 보이면, **Then** [작성자] 배지가 붙는다.
3. **Given** 비회원, **When** 글을 열면, **Then** 댓글은 보이고 입력칸 자리에 "로그인하고 댓글을 남겨 보세요 [로그인]"이 보이며,
   직접 작성 요청을 보내도 로그인이 필요하다며 거부된다.
4. **Given** 줄바꿈이 있고 `<script>`, `**굵게**`, 주소가 섞인 댓글, **When** 등록하면, **Then** 줄바꿈은 유지되고 HTML·Markdown·
   주소는 실행·변환·링크 없이 글자 그대로 보인다.
5. **Given** 정리한 뒤 비어 있거나 1000자를 넘는 댓글, **When** 등록하면, **Then** "댓글 내용을 입력해 주세요" / "댓글은 1000자까지
   쓸 수 있어요"와 함께 거부되고 입력한 내용은 그대로 남는다.
6. **Given** [등록]을 연달아 누르거나 같은 내용이 다시 전송됨, **When** 10초 안이면, **Then** 댓글은 하나만 생기고 처음 댓글이
   돌려진다.
7. **Given** 댓글이 없는 글, **When** 열면, **Then** "첫 댓글을 남겨 보세요"가 보인다.

### User Story 2 - 댓글에 답글을 단다 (Priority: P2)

회원은 댓글의 [답글]을 눌러 답한다. 답글은 항상 한 단계만 들여 쓰인다. 답글에 다시 답하면 같은 댓글 아래에 달리고 내용 위에
"@닉네임에게"로 대상이 표시된다.

**Why this priority**: 질문·답변 흐름을 만들지만 댓글(P1)이 먼저 있어야 한다.

**Independent Test**: 댓글 A에 답글 B를 달고, B에 다시 답해 C가 A 아래에 "@B작성자에게"와 함께 달리는지, 저장된 C의 소속이
A인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 최상위 댓글 A, **When** [답글]로 답하면, **Then** A 아래에 한 단계 들여 쓴 답글이 달리고 대상 표시는 없다.
2. **Given** A 아래의 답글 B, **When** B에 답하면, **Then** 새 답글은 A 아래에 달리고 내용 위에 "@B작성자닉네임에게"가 보인다.
3. **Given** 내 답글, **When** 내가 다시 거기에 답하면, **Then** A 아래에 달리고 "@내닉네임에게"로 대상이 표시된다(대댓글로
   보이게. 2026-10-13 민서님 신고 "대댓글이 작성 안 됨"으로 바꿈). 나에게는 알림이 가지 않는다.
4. **Given** 삭제된 자리, 숨겨진 댓글, 탈퇴한 사용자의 댓글, 다른 글의 댓글, **When** 그것에 답하려 하면, **Then** "답글을 달 수
   없는 댓글이에요"로 거부된다. 이런 댓글에는 [답글] 버튼이 보이지 않는다.
5. **Given** 대상 회원이 나중에 닉네임을 바꾸거나 탈퇴함, **When** 답글을 보면, **Then** 대상 표시는 지금 닉네임으로, 탈퇴했으면
   "탈퇴한 사용자에게"로 보인다. 대상 답글이 지워져도 대상 표시는 남는다.

### User Story 3 - 댓글을 오래된 순으로 이어 읽는다 (Priority: P3)

독자는 글 상세에서 오래된 순으로 첫 20개 댓글과 각 댓글의 처음 답글 3개를 보고, [댓글 더 보기]와 [답글 N개 더 보기]로 이어
읽는다. 알림에서 들어오면 그 댓글 위치로 바로 간다.

**Why this priority**: 댓글이 많아져도 글 상세가 가볍고 대화 흐름대로 읽히게 하지만, 쓰기가 먼저다.

**Independent Test**: 댓글 45개, 답글 8개가 달린 댓글이 있는 글을 열어 첫 20개와 처음 답글 3개 + [답글 5개 더 보기]가 보이는지,
같은 시각에 쓴 댓글이 커서 경계에 있어도 [댓글 더 보기]로 중복·누락 없이 이어지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 댓글이 20개보다 많은 글, **When** 글 상세를 열면, **Then** 최상위 댓글이 오래된 순으로 20개 함께 보이고 [댓글 더
   보기]가 있다. 더 없으면 버튼이 없다.
2. **Given** 답글 8개가 달린 댓글, **When** 보면, **Then** 처음 답글 3개와 [답글 5개 더 보기]가 보이고, 누르면 다음 답글이 한 번에
   20개씩 이어 붙는다.
3. **Given** 같은 시각에 쓴 댓글이 페이지 경계에 있음, **When** [댓글 더 보기]를 누르면, **Then** 중복·누락이 없다.
4. **Given** [댓글 더 보기]·[답글 더 보기], **When** 불러오는 중이면 "불러오는 중…"(비활성화), 실패하면 "불러오지 못했어요
   [다시 시도]"가 보이고, 이미 보이는 댓글은 그대로다.
5. **Given** 알림에서 특정 댓글로 들어옴, **When** 글 상세가 열리면, **Then** 그 댓글이 포함된 부분까지 불러와 스크롤하고 잠깐
   강조하며, 앞에 댓글이 더 있으면 [이전 댓글 보기]가 보인다. 대상이 4번째 이후 답글이면 그 답글까지 펼친다.
6. **Given** 그 글의 댓글이 아니거나 삭제·숨김·없는 댓글로 들어옴, **When** 열면, **Then** 오류 없이 첫 페이지가 보인다.
7. **Given** 다시 발행했거나 수정 중인 글, **When** 열면, **Then** 댓글은 그대로 이어서 보인다.

### User Story 4 - 내 댓글을 고치거나 지운다 (Priority: P4)

댓글 작성자는 자기 댓글을 언제든 고칠 수 있고 "수정됨"이 표시된다. 지우면 답글이 없는 댓글은 사라지고, 답글이 있는 최상위
댓글은 "삭제된 댓글이에요"로 자리만 남는다. 글 작성자도 남의 댓글은 지울 수 없다.

**Why this priority**: 실수를 바로잡게 하지만 쓰기·읽기가 먼저다.

**Independent Test**: 답글이 있는 내 최상위 댓글을 지워 자리만 남고 내용이 비워졌는지, 그 아래 마지막 답글이 지워지면 자리도
사라지는지, 글 작성자가 남의 댓글 삭제를 요청하면 거부되고 댓글이 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 내 정상 댓글, **When** 내용을 고쳐 저장하면, **Then** 바뀐 내용과 "· 수정됨"이 보인다. 소속·대상·작성 시각·댓글 수는
   바뀌지 않는다.
2. **Given** 내 댓글, **When** 정리한 뒤 같은 내용으로 저장하면, **Then** 아무것도 바뀌지 않고 "수정됨"도 붙지 않는다.
3. **Given** 답글이 없는 내 댓글(최상위 또는 답글), **When** 지우면, **Then** 댓글이 사라지고 댓글 수가 하나 준다.
4. **Given** 답글이 1개 이상 있는 내 최상위 댓글, **When** 지우면, **Then** 작성자 정보 없이 "삭제된 댓글이에요"로 자리만 남고
   내용은 비워지며 답글은 그대로 보이고 댓글 수가 하나 준다.
5. **Given** "삭제된 댓글이에요" 자리 아래 마지막 남은 답글, **When** 그 답글이 지워지면, **Then** 자리도 함께 사라진다.
6. **Given** 남의 댓글(내가 글 작성자인 경우 포함), **When** 수정·삭제를 요청하면, **Then** 없는 댓글과 같은 응답으로 거부되고
   댓글은 바뀌지 않는다. 화면에는 [수정]·[삭제] 대신 [신고]가 보인다.
7. **Given** 내 댓글을 지우는 순간 다른 사람이 그 댓글에 답글을 담, **When** 둘이 동시에 처리되면, **Then** 답글이 먼저면 내
   댓글은 자리로 남고, 삭제가 먼저면 답글은 "답글을 달 수 없는 댓글이에요"로 거부된다.
8. **Given** 등록·수정·삭제 중, **When** 버튼을 보면, **Then** 비활성화되고 "등록 중…" 등으로 바뀐다. 실패하면 입력한 내용이 그대로
   남는다.

### User Story 5 - 볼 수 없는 글의 댓글은 없는 것과 같다 (Priority: P5)

댓글은 그 글을 읽을 수 있는 사람만 보고 쓸 수 있다. 비공개·임시·휴지통 글의 댓글은 없는 글의 댓글과 똑같이 보인다. 글을
비공개로 바꾸면 댓글도 함께 숨고, 다시 공개하면 돌아온다.

**Why this priority**: 공개 범위 약속을 지키는 장치지만, 기본 흐름(P1~P4)이 먼저 있어야 한다.

**Independent Test**: 공개 글에 댓글을 단 뒤 비공개로 바꿔 다른 회원의 댓글 보기·쓰기·수정 요청이 없는 글과 똑같이 거부되는지,
다시 공개하면 댓글이 그대로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 임시·비공개(남의 글)·휴지통·없는 글, **When** 댓글 보기·쓰기·수정을 요청하면, **Then** 모두 같은 "찾을 수 없음"
   응답이다.
2. **Given** 읽을 수 없는 글, **When** 빈 내용으로 댓글을 쓰면, **Then** 내용 오류가 아니라 "찾을 수 없음"이다.
3. **Given** 댓글이 있는 공개 글, **When** 비공개로 바꾸면, **Then** 글 작성자만 댓글을 보고 쓸 수 있고 댓글은 지워지지 않으며,
   다시 공개하면 그대로 보인다.
4. **Given** 공개가 아닌 글, **When** 작성자가 댓글 목록을 받으면, **Then** 그 응답은 어디에도 저장되지 않는다(글 상세와 같은 규칙).

### Edge Cases

- 탈퇴를 신청한 사람의 댓글은? → 작성자 "탈퇴한 사용자", 내용 "탈퇴한 사용자의 댓글이에요"로 보이고 댓글 수에는 그대로 센다.
  복구하면 원래대로 돌아온다.
- 관리자가 숨긴 댓글은? → 다른 사람에게는 작성자 정보 없이 "운영 정책에 따라 숨겨진 댓글이에요", 작성자 본인에게는 원문 +
  "숨겨졌어요 (나만 보여요)". 수정은 "숨겨진 댓글은 수정할 수 없어요"로 거부, 답글 불가, 작성자 본인 삭제는 가능. 숨겨진 최상위
  아래의 답글은 그대로 보인다.
- 여러 상태가 겹치면? → 탈퇴 → 삭제된 자리 → 숨김 → 정상 순서로 먼저 해당하는 하나를 적용한다.
- 이모지가 든 댓글의 길이는? → 글자 단위로 센다(이모지 하나 = 1자). 화면과 서버의 글자 수가 같아야 한다.
- `\r\n` 줄바꿈, 연달은 빈 줄, 보이지 않는 글자는? → `\n`으로 바꾸고, 빈 줄은 하나로 합치고, 보이지 않는 글자·방향 제어 문자·제어
  문자는 지우되 줄바꿈은 남긴다.
- 욕설처럼 보이는 단어는? → 금칙어 필터 없이 그대로 받는다(오탐 방지). 문제 댓글은 신고로 처리한다.
- 1분에 댓글 11개를 쓰거나 수정 21번을 하면? → "잠시 후 다시 시도해 주세요"와 함께 거부된다. 이 거부는 글이 있는지와 무관하게
  같다.
- 정지된 회원은? → 로그인할 수 없으므로 댓글을 쓸 수 없고, 이미 쓴 댓글은 그대로 보인다.
- 글이 완전히 삭제되면? → 그 글의 댓글도 함께 지워진다.
- 글 작성자가 탈퇴 유예 중이거나 관리자가 글을 숨기면? → 댓글 쓰기는 "찾을 수 없음"이고 댓글 행은 유지된다.
- 삭제한 댓글을 되살릴 수 있는가? → 없다.

## Requirements *(mandatory)*

### Functional Requirements

**권한 (docs/42 §3·§6, docs/21 §5)**

- **FR-001**: 댓글 쓰기·답글은 로그인하고 가입을 마친 회원만 할 수 있어야 한다. 이메일 인증 전 회원은 쓸 수 없다(GitHub 가입은
  인증된 이메일이 필수라 이번 범위에서는 해당자가 없다).
- **FR-002**: 댓글을 보고 쓰려면 그 글을 읽을 수 있어야 한다(003의 판정 규칙). 발행되지 않았거나, 휴지통이거나, 공개 범위상 볼 수
  없는 글은 보기·쓰기·수정 모두 없는 글과 같은 "찾을 수 없음"이어야 한다.
- **FR-003**: 작성 요청은 ① 로그인 ② 계정 상태(탈퇴 유예·인증 전) ③ 요청 제한 ④ 글을 읽을 수 있나 ⑤ 내용 ⑥ 대상 댓글 순으로
  검사하고 처음 걸린 단계의 결과를 줘야 한다.
- **FR-004**: 수정·삭제는 댓글 작성자 본인만 할 수 있어야 한다. 글 작성자·관리자를 포함한 남의 요청은 없는 댓글과 같은 응답으로
  거부하고 댓글은 바뀌지 않아야 한다(CM-10).
- **FR-005**: 화면에서도 [수정]·[삭제]는 본인의 정상 댓글에만, [답글]은 정상 상태 댓글에만, [신고]는 남의 정상 댓글에만 보여야
  하지만, 화면 숨김과 상관없이 서버가 다시 검사해야 한다.

**형식 (CM-5·CM-6, docs/21 §4)**

- **FR-006**: 댓글은 ① 유니코드 정규화 ② 보이지 않는 글자·방향 제어 문자·제어 문자 제거(줄바꿈은 남김) ③ `\r\n`을 `\n`으로
  ④ 앞뒤 공백 제거 ⑤ 연달은 빈 줄을 하나로 정리한 뒤 1~1000자(글자 단위, 이모지 하나 = 1자)여야 한다.
- **FR-007**: 댓글은 글자만이다. HTML·Markdown은 쓴 그대로 글자로 보이고, 주소는 링크로 바꾸지 않으며, 줄바꿈은 유지해야 한다.
  어떤 입력으로도 스크립트가 실행되지 않아야 한다.
- **FR-008**: 금칙어 필터는 두지 않는다. 이모지는 허용한다.
- **FR-009**: 실패 이유는 "내용 없음", "1000자 초과", "답글을 달 수 없는 댓글", "숨겨진 댓글은 수정 불가", "잠시 후 다시 시도"를
  구별해 화면 문구로 보여야 한다.

**작성과 답글 구조 (CM-1·CM-2·CM-12·CM-13, docs/21 §2·§5)**

- **FR-010**: 답글은 1단계만이다. 저장된 답글의 소속은 항상 최상위 댓글이어야 한다.
- **FR-011**: 최상위 댓글에 답하면 그 댓글 아래에 대상 없이, 답글에 답하면 같은 최상위 아래에 그 답글 작성자를 대상으로 저장해야
  한다. 내 답글에 내가 답해도 대상(나)을 남긴다(알림은 FR-005①이 거른다). 대상은 댓글이 아니라 회원을 가리켜 대상 답글이 지워져도 남아야 한다.
- **FR-011a**: 답글에 답하면 답한 답글 번호도 남겨, 화면이 Git 브랜치 그래프처럼 답한 답글의 프로필에서 세로선을 내려 둥글게 꺾어
  새 답글로 잇는다. 깊이마다 선 색이 바뀌고 3단계까지만 들여 쓰며 더 깊은 답글은 3단계 가지에 나란히 둔다. 저장 구조는 그대로
  깊이 1(소속은 늘 최상위)이라 삭제·탈퇴·댓글 수 규칙은 바뀌지 않는다. 답한 답글 행이 지워지면 번호는 비고 최상위에서 갈라진
  것으로 그린다 (V35, 2026-10-13 민서님 요청 "대댓글에 대한 구분도 깃 브랜치처럼 구분지어지게").
- **FR-012**: 답글 대상 댓글은 같은 글의 정상 상태(삭제·숨김·작성자 탈퇴 아님) 댓글이어야 하며, 아니면 거부해야 한다. 다른 글의
  댓글을 소속으로 지정할 수 없어야 한다.
- **FR-013**: 같은 사람이 같은 글에 같은 내용·같은 대상으로 10초 안에 다시 보내면 새로 만들지 않고 처음 댓글을 돌려줘야 한다.
- **FR-014**: 작성은 사용자당 1분에 10개로 제한해야 한다.
- **FR-015**: 댓글 수는 저장하지 않고 "삭제되지 않고 숨겨지지 않은 댓글 수"를 세어 보여야 한다(`post_stat` 뷰). 작성이 끝나면
  같은 처리 안에서 센 값이 바로 1 늘어난다.
- **FR-016**: 글 작성자가 쓴 댓글에는 [작성자] 배지를 보여야 한다.
- **FR-017**: 작성이 끝나면 "댓글이 작성됨" 사건(댓글, 글, 글 작성자, 댓글 작성자, 소속 댓글과 그 작성자, 답글 대상 회원, 시각)을
  알려야 한다. 사건에는 댓글 내용·닉네임 같은 글자를 넣지 않고, 이 사건을 받는 기능이 실패해도 댓글 작성은 성공해야 한다
  (docs/20 §3-2).

**표시 (CM-9, docs/21 §3)**

- **FR-018**: 댓글은 탈퇴한 사람의 댓글 → 삭제된 자리 → 관리자 숨김 → 정상 순서로 먼저 해당하는 상태 하나로 보여야 한다. 문구는
  각각 "탈퇴한 사용자의 댓글이에요"(작성자 "탈퇴한 사용자"), "삭제된 댓글이에요", "운영 정책에 따라 숨겨진 댓글이에요"(작성자
  본인에게는 원문 + "숨겨졌어요 (나만 보여요)")다.
- **FR-019**: 삭제된 자리·탈퇴한 사람의 댓글·남이 보는 숨긴 댓글은 내용과 작성자 정보를 내려보내지 않아야 한다.
- **FR-020**: 정상 댓글은 프로필 사진(없으면 기본 아이콘) + `닉네임 @블로그주소`(누르면 그 블로그), 작성 시각(24시간 이내 "N시간
  전", 이후 `2026.10.02`), 내용을 보이고, 내용을 고친 적이 있으면 "· 수정됨"을 보여야 한다.
- **FR-021**: 답글 대상이 있으면 내용 위에 "@지금닉네임에게"를, 대상이 탈퇴했으면 "탈퇴한 사용자에게"를 보여야 한다.
- **FR-022**: 비회원에게는 입력칸 자리에 "로그인하고 댓글을 남겨 보세요 [로그인]"을, 이메일 인증 전 회원에게는 "이메일 인증 후
  댓글을 쓸 수 있어요 [인증 메일 다시 보내기]"를 보여야 한다.
- **FR-023**: 댓글 요소마다 위치 표시를 두어 알림 등에서 특정 댓글로 바로 갈 수 있어야 한다.

**목록 (CM-3·CM-4·CM-11, docs/21 §6)**

- **FR-024**: 최상위 댓글은 오래된 순(같으면 번호 작은 순)으로 20개씩, 각 최상위 아래 답글은 처음 3개를 함께 보이고 나머지는
  [답글 N개 더 보기]로 한 번에 20개씩 보여야 한다. N은 그 최상위 아래 답글 수(숨긴 답글 포함)다. 답글이 5개 이하면 접지 않고
  모두 함께 보인다([답글 1~2개 더 보기]를 누르게 하지 않는다, 2026-10-14 민서님 요청).
- **FR-025**: 목록은 내용을 알 수 없는 커서로 이어 붙이며, 같은 시각의 댓글이 경계에 있어도 중복·누락이 없어야 하고, 마지막 판단
  때문에 빈 결과 클릭이 생기지 않아야 한다. 고친 커서·다른 목록의 커서는 거부해야 한다.
- **FR-026**: 글 상세를 열면 첫 20개 댓글(각 처음 답글 3개 포함)이 함께 보여야 한다.
- **FR-027**: 특정 댓글부터 보기를 요청하면 그 댓글의 최상위부터 20개를 보이고, 앞에 댓글이 더 있으면 [이전 댓글 보기]를
  제공하며, 대상이 4번째 이후 답글이면 그 답글까지 펼쳐야 한다. 그 글의 댓글이 아니거나 삭제·숨김·없는 댓글이면 오류 없이 첫
  페이지를 보여야 한다(있는지 드러내지 않음).
- **FR-028**: 머리말의 "댓글 N"은 글의 댓글 수이며, 이는 항상 "삭제되지 않고 숨겨지지 않은 댓글(최상위 + 답글) 수"와 같아야
  한다. 탈퇴 유예 중인 사람의 댓글은 센다. 작성 +1, 삭제 −1, 숨김 −1, 해제 +1, 탈퇴 정리 −n이며 모두 같은 처리 안에서 바뀐다.
  목록 카드의 댓글 수도 이 값이다.
- **FR-029**: 댓글 목록 한 페이지는 두 번의 조회로 그려야 한다(댓글마다 추가 조회 없음).
- **FR-030**: 공개가 아닌 글의 댓글 응답은 어디에도 저장되지 않아야 한다.

**수정 (CM-7, docs/21 §7)**

- **FR-031**: 작성자는 정상 상태의 자기 댓글을 언제든 고칠 수 있어야 한다. 삭제된 자리는 없는 댓글로, 숨겨진 댓글은 "숨겨진
  댓글은 수정할 수 없어요"로 거부해야 하며, 지금 그 글을 읽을 수 있어야 한다.
- **FR-032**: 수정은 내용과 "내용을 바꾼 시각"만 바꾸고, 소속·대상·작성 시각·댓글 수는 바꾸지 않아야 한다. 정리 후 내용이 같으면
  아무것도 바꾸지 않아야 한다. "수정됨"은 내용을 바꾼 경우에만 붙는다.
- **FR-033**: 수정 이력은 남기지 않고, 수정 사건·알림도 보내지 않는다. 수정은 사용자당 1분에 20번으로 제한해야 한다.

**삭제 (CM-8, docs/21 §8)**

- **FR-034**: 답글이 1개 이상 있는 최상위 댓글을 지우면 내용을 비우고 "삭제된 댓글이에요" 자리로 남겨야 한다. 그 밖의 댓글(답글
  없는 최상위, 모든 답글)은 행을 지워야 한다.
- **FR-035**: 답글을 지웠을 때 그 최상위가 삭제된 자리이고 남은 답글이 없으면 자리도 지워야 한다.
- **FR-036**: 삭제하면 그 댓글은 보이는 댓글 수에서 빠진다(세어서 구하므로 따로 줄이지 않는다). 숨긴 상태였던 댓글은 이미
  빠져 있고, 자리를 지울 때도 수는 그대로다.
- **FR-037**: 숨겨진 내 댓글도 지울 수 있어야 한다. 삭제는 되돌릴 수 없다.
- **FR-038**: 삭제와 답글 작성이 동시에 오면 순서를 정해, 답글이 먼저면 자리로 남기고 삭제가 먼저면 답글을 거부해야 한다.
- **FR-039**: 삭제하면 "댓글이 삭제됨" 사건(댓글, 글, 글 작성자, 댓글 작성자, 소속 댓글, 시각)을 알려야 한다. 그 댓글로 생긴 알림은
  이 사건으로 지운다(docs/20 §3-2·§4-2).

**글 상태·관리자 숨김·탈퇴 연동 (docs/21 §9~§11)**

- **FR-040**: 글 상태에 따라 임시글은 보기·쓰기 모두 없는 글로, 공개 글은 누구나 보고 회원이 쓰며, 비공개 글은 글 작성자만 보고
  쓰고(댓글 유지), 수정 중인 글은 발행본 기준 그대로, 휴지통 글은 없는 글로(댓글 유지), 완전 삭제된 글은 댓글도 함께 지우고,
  작성자 탈퇴 유예 중인 글과 관리자가 숨긴 글은 쓰기를 없는 글로(댓글 유지) 다뤄야 한다.
- **FR-041**: 관리자가 댓글을 숨기면 보이는 댓글 수에서 빠지고 해제하면 다시 들어가야 한다(세어서 구한다). 숨긴 댓글은 수정·답글
  불가, 작성자 본인 삭제 가능이다.
- **FR-042**: 탈퇴 유예 중에는 댓글 행과 댓글 수를 그대로 두고 화면에서만 탈퇴 표시를 하며, 복구하면 돌아와야 한다. 30일 뒤 정리에서
  남의 답글이 달린 내 최상위 댓글은 자리로 남기고, 나머지 내 댓글은 지우며, 그로 인해 빈 자리는 지우고, 지운 만큼 각 글의 댓글 수를
  줄여야 한다. 정리는 내 글 완전 삭제 다음에 해야 한다. 다른 사람 답글의 대상 표시는 "탈퇴한 사용자에게"로 남는다.

### Key Entities *(include if feature involves data)*

- **댓글(Comment)**: 글, 작성자, 소속 최상위 댓글(최상위면 없음), 답글 대상 회원(답글에 답한 경우만), 내용(1~1000자), 작성
  일자, 내용 수정 일자, 삭제 일자(자리로 남은 경우), 관리자 숨김 일자·처리자·사유. 소속은 같은 글의 댓글만 가능하다.
- **글(Post)**: 002에서 정의. 댓글 수는 글에 저장하지 않고 세어서 구한다.
- **회원(Member)**: 001에서 정의. 작성자 표시와 답글 대상 표시에 지금 닉네임·블로그 주소·프로필 사진, 탈퇴 여부를 쓴다.
- **댓글 커서(Cursor)**: 마지막으로 본 댓글의 작성 시각과 번호를 담은, 내용을 알 수 없는 값.

### V3 정규화 반영 (2026-10-07)

근거: `erd/normalization-v3.md`, Crowfoot ERD 요구사항 REQ-025·REQ-027. 다른 값에서 계산되는 값은 저장하지 않는다.

- 답글은 1단계라 재귀 쿼리가 필요 없다. "답글의 부모는 최상위 댓글" 규칙을 DB가 막는다: 생성 컬럼 `is_root`·`parent_is_root`와

- 클로저 테이블과 비교한 성능 측정(댓글 102만 개): 첫 화면 0.23ms 대 0.71ms, 답글 쓰기 0.69ms 대 1.18ms, 저장 공간 242MB 대 431MB.

  거부)이 모두 자동 테스트로 확인된다.

## Assumptions

- **A-1 (2026-10-07 확정)**: MVP 로그인은 GitHub 단독이고 GitHub 가입은 인증된 이메일이 필수이므로 "이메일 인증 전 회원" 상태는
  이번에 생기지 않는다. 이메일 가입이 들어오면 인증 전 회원은 댓글 쓰기 불가, 본인 댓글 삭제는 허용(docs/42 §6)이 그대로 적용된다.
- **A-2 (2026-10-07 확정)**: 글 상세는 화면이 데이터를 받아 그리는 방식이며, 스크립트가 없을 때를 위한 서버 대체 링크 규칙은 두지
  않는다(docs/21 §6의 대체 링크 규칙은 2026-10-07 H7로 삭제됨). "첫 20개"는 글 상세를 열 때 함께 보이는 것으로 해석한다.
- **A-3**: 신고, 관리자 숨김·해제 기능, 회원 탈퇴, 인앱 알림은 각자의 기능에서 다룬다. 이 spec은 그 기능들이 들어올 때 댓글 쪽에서
  지켜야 할 표시·댓글 수·정리 규칙(FR-018, FR-039~042)과 특정 댓글부터 보기(FR-027)를 먼저 정해 둔다.
- **A-4**: 답글 깊이 무제한(3단계까지 펼침)은 개인 확장이며 범위 밖이다. 켜더라도 이 spec의 완료 기준을 그대로 만족해야 하고,
  자식이 있는 모든 댓글을 자리로 남겨야 한다.
- **A-5**: 글 작성자가 남의 댓글을 지우는 권한은 개인 확장이며 공통에서는 두지 않는다(공통 변경은 회의 제안만, 미결).
- **A-6**: 신고된 댓글이 작성자 삭제로 사라져도 검토할 수 있도록 신고 때 내용을 복사해 두는 것은 신고 기능에서 정한다(미결).
- **A-7**: 조회 요청 제한은 공통 IP 제한을 따르며 댓글 전용 제한은 두지 않는다.
