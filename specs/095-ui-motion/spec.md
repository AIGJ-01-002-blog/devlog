# Feature Specification: 화면 움직임으로 부드러운 사용감

**Feature Branch**: `feature/ui-motion-2wgkcb` (이슈 #176, 목표 #169)
**Created**: 2026-10-12
**Status**: Implemented (develop, 버전은 릴리스 때)
**근거**: 민서님 요청(2026-10-12) "우리 ui에 에니메이션이나 이펙트가 없는거 같은데 한번 추가해서 사용자가 우리 블로그를 이용하면서 부드러운 사용감을 줄 수 있도록 설계해서 gif로 보여줘". 설계: docs 저장소 `design/46-ui-motion.md`.

## 원칙
- 새 라이브러리 없이 CSS 전환·애니메이션으로, `transform`·`opacity`만 움직인다(레이아웃을 다시 계산하지 않는다).
- 짧게: 누름·메뉴 0.12초, 모달·띠 0.2초, 목록 등장 0.32초. 곡선은 빨리 시작해 부드럽게 멈추는 `--ease-out`.
- 나타날 때만 움직이고 닫을 때는 바로 닫는다.
- 첫 화면은 움직이지 않는다(첫 화면 시간·LCP 보호). 운영체제의 '동작 줄이기'를 켜면 모두 끈다.

## Requirements
- **FR-001**: 화면을 옮기면 본문 자리가 0.18초 동안 흐림에서 또렷해진다. 첫 화면에서는 하지 않는다. 본문 자리에 transform을 걸지 않는다(안의 position: fixed가 흔들리지 않게).
- **FR-002**: 새로 받은 글 목록(카드, 첫 화면 브랜치 목록의 글 내용)이 아래에서 10px 올라오며 나타나고, 앞 6줄은 0.04초씩 엇갈린다. 첫 화면 브랜치 목록은 줄기 그림은 그대로 두고 글 내용만 움직인다. 이 효과는 사용자의 첫 스크롤·클릭·키 입력 뒤(`html.motion-ready`)에만 켠다.
- **FR-003**: 모달은 막이 흐려지며 나타나고 상자가 8px 아래에서 살짝 커지며 뜬다. 내 메뉴·알림·언어 목록은 단추 쪽(오른쪽 위)에서 펼쳐진다. 알림 띠는 위에서 내려온다. 알림 개수 배지는 튀어나온다.
- **FR-004**: 버튼·칩·둘 중 하나 고르기·아래 탭 아이콘은 누르는 동안 살짝 작아진다(0.96~0.97배). 최신·트렌딩 탭, 브랜치 칩의 고른 칸 바탕은 색이 부드럽게 바뀐다.
- **FR-005**: 좋아요를 막 누르면 하트가 한 번 튄다(1.35배). 처음부터 눌려 있던 글은 움직이지 않는다.
- **FR-006**: 동작 줄이기를 켜면 전환·애니메이션 시간과 엇갈림 지연을 모두 0으로 하고, 화면 이동 흐림도 하지 않는다.

## 고른 기본값 (질문 없이 정함)
- 카드에 마우스를 올렸을 때 뜨는 효과는 넣지 않았다. 068에서 "모든 카드가 움직이면 산만하고 휴대폰에서 뜬 채로 남는다"는 이유로 뺀 결정을 지킨다.
- 닫힘 애니메이션은 넣지 않았다. 닫힐 때까지 컴포넌트를 남겨 두는 코드가 늘고, velog도 바로 닫는다.
- 화면 이동은 opacity만 쓴다. View Transitions API는 브라우저 지원이 고르지 않고 강사님이 지적한 과한 구성에 가깝다.
